# Evaluating long-term memory for LLM agents: benchmarks, methodology, failure modes, attacks, and mitigations (2025–2026)

Scope note: this file covers (a) benchmarks/metrics, (b) methodology for proving memory helps, (c) failure modes and attacks, (d) mitigations and production safeguards. Pre-2025 work is marked "[older]". Where a number is self-reported by a vendor it is marked "(vendor self-report)". Findings are tied to the Ratchet pattern (read-only grader, hidden held-out split, measured noise band, leakage critic) in the Inferences subsections.

---

## Key Question 1: Which benchmarks are considered credible in 2026, what do top systems score, and what are their known weaknesses?

### Takeaway
By 2026 the field has split into (i) conversational-recall benchmarks (LoCoMo, LongMemEval, BEAM) that are near-saturated (top systems 85–95%) and have documented ground-truth and judge-reliability problems, and (ii) a newer generation of "memory over task streams" benchmarks (MemoryAgentBench, Evo-Memory, MemoryArena, Memora/FAMA, STALE, LongMemEval-V2) where success rates are far lower and where memory is tested as something the agent writes and reuses across tasks rather than retrieves from a fixed transcript. For a research-agent harness like Ratchet, the second class is the relevant model; the first class mostly measures retrieval over a transcript.

### Cited Findings

**Conversational-recall benchmarks and their scores**

- LongMemEval (ICLR 2025) tests five abilities — information extraction, multi-session reasoning, temporal reasoning, knowledge updates, and abstention — with 500 curated questions over scalable chat histories; commercial assistants and long-context LLMs showed a ~30% accuracy drop on sustained-interaction memorization. It frames memory design as three stages: indexing, retrieval, reading. — [LongMemEval, arXiv 2410.10813](https://arxiv.org/abs/2410.10813); [ICLR 2025 proceedings](https://proceedings.iclr.cc/paper_files/paper/2025/hash/d813d324dbf0598bbdc9c8e79740ed01-Abstract-Conference.html) [older: Oct 2024, revised Mar 2025]
- LongMemEval's project page reports long-context LLMs show a 30–60% drop on LongMemEval-S and commercial systems (e.g., GPT-4o) reach only 30–70% in a simpler setting. — [LongMemEval project page](https://xiaowu0162.github.io/long-mem-eval)
- LongMemEval scoring uses an LLM judge with a binary correct/wrong label; LoCoMo (Snap Research, ACL 2024 [older]) uses F1 plus LLM grading. — [MaxiMem "claimed vs observed"](https://www.maximem.ai/blog/state-of-ai-memory-2026-claimed-vs-observed); [Mem0 State of AI Agent Memory 2026](https://mem0.ai/blog/state-of-ai-agent-memory-2026)
- Mem0 (vendor self-report, Oct 2026) reports LoCoMo 92.5 (~6,956 tokens/query), LongMemEval 94.4 (~6,787 tokens/query), BEAM-1M 64.1, BEAM-10M 48.6. — [Mem0 State of AI Agent Memory 2026](https://mem0.ai/blog/state-of-ai-agent-memory-2026); per-type LongMemEval breakdown (knowledge-update 93.6%, multi-session 88–93%) in [mem0ai/memory-benchmarks](https://github.com/mem0ai/memory-benchmarks)
- Academic systems report comparable top-end scores: APEX-MEM with Claude 4.5 Sonnet reports 86.2% overall on LongMemEval (ACL 2026); MemMachine reports 91.69% on LoCoMo (gpt-4.1-mini) and 93.0% on LongMemEval-S ablation-best (gpt-5-mini). — [APEX-MEM, ACL 2026](https://aclanthology.org/2026.acl-long.749.pdf); [MemMachine, arXiv 2604.04853](https://arxiv.org/html/2604.04853v1)
- Mem0's own April 2025 paper reported 66.88 on LoCoMo, versus 92.5 in its benchmark repo a year later; the Mem0 paper reported Zep at 65.99, Zep re-ran with a corrected harness and reported 75.14; Mem0's counter-analysis argued Zep's separate 84% claim falls to 58.44 under Mem0's harness. — [Mnemoverse, LLM-as-Judge variance](https://mnemoverse.com/docs/research/evaluation/judges-good-and-evil); [Zep issue #5 (Mem0 CTO)](https://github.com/getzep/zep-papers/issues/5); [Zep correction, memobase issue #101](https://github.com/memodb-io/memobase/issues/101); [Mem0 paper, arXiv 2504.19413](https://arxiv.org/abs/2504.19413)
- Mem0's paper claims 26% relative improvement in LLM-as-judge over OpenAI's memory on LoCoMo, 91% lower p95 latency and >90% token savings vs full-context. (vendor self-report, peer status: arXiv) — [Mem0 paper](https://arxiv.org/abs/2504.19413)

**Known weaknesses of LoCoMo / LongMemEval**

- Independent audit (Penfield Labs, Apr 2026, one team, not peer-reviewed): 99 of 1,540 LoCoMo questions (6.4%) have score-corrupting answer-key errors (hallucinated facts, wrong temporal reasoning, speaker attribution); the standard gpt-4o-mini judge accepted 62.81% of intentionally wrong but topically adjacent answers, while catching specific factual errors ~89% of the time. There is no standardized pipeline; each system uses its own ingestion, prompts, and sometimes models. Multiple groups report inability to reproduce published numbers. — [Penfield Labs audit](https://penfieldlabs.substack.com/p/we-audited-locomo-64-of-the-answer); audit repo [dial481/locomo-audit](https://github.com/dial481/locomo-audit)
- The same audit argues LongMemEval-S is "more of a context window test than a memory test" because each question's corpus fits in modern context windows. — [Penfield Labs audit](https://penfieldlabs.substack.com/p/we-audited-locomo-64-of-the-answer)
- Northcutt et al. (NeurIPS 2021 [older]) measured an average 3.3% label error rate across ten ML benchmarks; LoCoMo's 6.4% is nearly double. — [Penfield Labs audit](https://penfieldlabs.substack.com/p/we-audited-locomo-64-of-the-answer)
- Judge choice alone moves scores massively: a 2026 paper documents a 27.5-point macro gap between strict token-F1 and a generous LLM judge on identical LoCoMo outputs (59.97 vs 32.45). — [When Does Belief-Based Agent Memory Help?, arXiv 2606.22030](https://arxiv.org/pdf/2606.22030v2)
- Mem0's own guidance now says to treat any benchmark without a published audit as having an unknown (not zero) error rate, and that LoCoMo and LongMemEval have been public long enough that contamination is a concern. — [Mem0, How to Read Memory Benchmarks](https://mem0.ai/library/agent-memory/how-to-read-memory-benchmarks)
- Annotation errors have also been reported directly on the Mem0 evaluation repo (7 items with out-of-range evidence references). — [mem0 discussion #3502](https://github.com/mem0ai/mem0/discussions/3502)
- LoCoMo-Plus (Feb 2026) adds "cognitive memory" questions where the cue and trigger are semantically disconnected and shows string-matching metrics are misaligned; but the audit notes it inherits all 1,540 original questions (including the 99 errors) and its improved three-tier judging was validated only on new questions. — [LoCoMo-Plus, arXiv 2602.10715](https://arxiv.org/abs/2602.10715); [Penfield Labs audit](https://penfieldlabs.substack.com/p/we-audited-locomo-64-of-the-answer)
- MemoryArena authors: agents with "near-saturated performance" on LoCoMo "perform poorly" in an agentic multi-session setting, "exposing a gap in current evaluations." — [MemoryArena, arXiv 2602.16313](https://arxiv.org/abs/2602.16313)

**Longer-horizon and multi-ability benchmarks**

- BEAM (ICLR 2026): 100 coherent conversations at 128K/500K/1M/10M tokens and 2,000 human-validated probes across 10 memory abilities; even 1M-context LLMs with/without retrieval degrade as dialogues lengthen; the accompanying LIGHT framework (episodic + working memory + scratchpad) improves 3.5–12.69% over strongest baselines. — [BEAM, arXiv 2510.27246](https://arxiv.org/abs/2510.27246); [project page](https://mohammadtavakoli78.github.io/beam-light)
- MemBench (ACL 2025 Findings): separates factual vs reflective memory, participation vs observation scenarios, and reports four metrics — accuracy, recall, capacity, efficiency — with sub-datasets at ~10k and ~100k tokens/session. — [MemBench, arXiv 2506.21605](https://arxiv.org/abs/2506.21605); [ACL anthology](https://aclanthology.org/2025.findings-acl.989.pdf)
- MemoryAgentBench (ICLR 2026): four competencies — Accurate Retrieval (AR), Test-Time Learning (TTL), Long-Range Understanding (LRU), Selective Forgetting (SF) — over 2,071 questions at 103K–1.44M context. Overall scores: GPT-4o long-context 48.8, GPT-4o-mini 42.2, HippoRAG-v2 41.6, MemoRAG 30.9, Mem0 21.1. All methods fail multi-hop selective forgetting (≤28%). Mem0 and Cognee score "significantly lower than their backbone GPT-4o-mini even when the context is relatively small." Latency: Mem0 memory-construction 10,804 s vs BM25 0.12 s on MH-QA (512-token chunks). — [MemoryAgentBench, arXiv 2507.05257](https://arxiv.org/html/2507.05257v4); [OpenReview](https://openreview.net/forum?id=DT7JyQC3MR)
- MemoryAgentBench reviewers flagged that the TTL tasks "might be conflating memory length with learning ability" and inherently favor long-context models over RAG; the SF task was criticized as artificial. — [OpenReview meta-review](https://openreview.net/forum?id=DT7JyQC3MR)
- MemoryAgentBench's zero-shot control: with no access to history, models score <4% average on TTL tasks vs 48.6% with full history (+45.2 pp), used to argue gains are from the history and not pretraining. — [MemoryAgentBench appendix H](https://arxiv.org/html/2507.05257v4)
- Compute-matched comparison (same token budget): at ~4K budget RAG (BM25) beats long-context 83.0 vs 74.0 on Banking77 TTL; at ~104K long-context reaches 93.0 while RAG "saturates and slightly degrades (88.0) due to retrieved noise." — [MemoryAgentBench appendix J](https://arxiv.org/html/2507.05257v4)

**Memory over task streams (test-time learning / self-evolving memory)**

- Evo-Memory (Google, Nov 2025, rev. May 2026): a streaming benchmark where datasets become sequential task streams and the agent must search, adapt, and evolve memory after each task; >10 memory modules evaluated across 10 datasets (AlfWorld, BabyAI, PDDL, ScienceWorld, AIME-24/25, GPQA, MMLU-Pro, ToolBench). Metrics: answer accuracy, success rate, progress rate, step efficiency, cumulative accuracy over the stream. — [Evo-Memory, arXiv 2511.20857](https://arxiv.org/html/2511.20857v2)
- Evo-Memory results: gains are modest in single-turn reasoning (Claude 3.7 Sonnet avg 0.54 baseline → 0.58–0.59 for ReMem/ExpRAG; several memory modules e.g. LangMem 0.49 and AWM 0.48 fall below baseline) and larger in multi-turn environments (AlfWorld steps 22.6 → 11.5 with ReMem). Gains correlate with task-embedding cluster ratio (recurring structure); AIME-25/GPQA show small gains. Storing unfiltered failures causes "notable degradation" for baselines. — [Evo-Memory §4.2](https://arxiv.org/html/2511.20857v2)
- MemoryArena (Feb 2026, rev. Sep 2026): human-crafted multi-session agentic tasks with interdependent subtasks across web shopping, group travel planning, progressive web search, and formal reasoning; metrics are Success Rate, Progress Score, soft Progress Score, and latency. Long-context agents averaged 0.09–0.19 all-task SR; two environments show near-zero SR for all methods; external-memory systems (Letta, Mem0, Mirix, ReasoningBank) always had the highest latency (e.g., Mem0 706 s avg vs GPT-4.1-mini long-context 217 s). — [MemoryArena, arXiv 2602.16313](https://arxiv.org/html/2602.16313v2)
- MemoryArena notes Evo-Memory reuses independent single-session tasks sequentially, so there is "no explicit subtask-level dependency or cross-session causal structure enforced." — [MemoryArena related work](https://arxiv.org/html/2602.16313v2)
- LongMemEval-V2 (2026): shifts to multimodal web-agent trajectory histories (25M–115M tokens, 451 questions) testing static state recall, dynamic state tracking, workflow knowledge, environment gotchas, and premise awareness; scores both accuracy and query latency and ranks via "LAFS Gain" (accuracy-latency frontier over log-scaled latency budgets 1–200 s). Reference points: no retrieval 1.3%, RAG 42.8% (0.1 s), Codex 69.9% (177 s), AgentRunbook-C 74.9% (108 s). — [LongMemEval-V2 page](https://xiaowu0162.github.io/longmemeval-v2)
- Memora (ACL 2026 Findings) stresses consolidation and mutation over weeks–quarters (quarterly: avg 28.4 consolidation events, 14.8 mutations per question vs LoCoMo 1.3 / 0.0) and introduces Forgetting-Aware Memory Accuracy (FAMA) penalizing reliance on invalidated memory. Memory agents degrade sharply from weekly to quarterly on remembering (MemoBase 43.6 → 15.18, MemoryOS 51.84 → 25.05, Mem0 40.42 → 19.90); "memory agents offer marginal improvements." — [Memora, arXiv 2604.20006](https://arxiv.org/html/2604.20006v1); [ACL anthology](https://aclanthology.org/2026.findings-acl.1337)
- STALE (May 2026): 400 expert-validated conflict scenarios (1,200 queries, contexts to 150K) probing whether agents detect that a prior memory is invalidated, including "Implicit Conflict" without explicit negation. — [STALE, arXiv 2605.06527](https://arxiv.org/abs/2605.06527v1)
- A 2026 survey tabulates benchmark coverage (multi-session, multi-turn, agentic tasks, forgetting, multimodal) and concludes "nobody evaluates forgetting well. Only MemoryAgentBench tests" selective forgetting, and "long context is not memory": long-context models underperform purpose-built memory systems on selective retrieval. — [Memory for Autonomous LLM Agents survey, arXiv 2603.07670](https://arxiv.org/html/2603.07670v1)

**Benchmarks relevant to coding/research agents**

- Proactive Memory Agent (Aug 2026) evaluates memory on Terminal-Bench 2.0 (85 paired tasks, hidden verifier tests) and τ²-Bench: Sonnet 4.5 37.6% → 45.9% (+8.3 pp) on Terminal-Bench, 55.0% → 61.8% (+6.8 pp) on τ²-Bench; Opus 4.6 gains +2.4/+2.5 pp. Mem0 as a drop-in memory improved average but not every domain. — [Remember When It Matters, arXiv 2607.08716](https://arxiv.org/html/2607.08716v1)
- "When Self-Evolution Backfires" uses Terminal-Bench 2 with a three-way split (Event 50 / Holdout 14 / Test 25) and TB2's deterministic verifier with "no LLM grader." — [arXiv 2608.05810](https://arxiv.org/html/2608.05810v1)
- GDPevo (Aug 2026) is an "evolution-native" benchmark for enterprise workflows with 5 train / 5 held-out test tasks per group and rule hybridization so test gains are attributable; it reports self-evolution improving held-out accuracy by up to +16.44 pp (Opus-4.8) and treats tokens/turns/cost as first-class metrics. — [GDPevo, arXiv 2608.03764](https://arxiv.org/html/2608.03764v1)
- SWE-rebench (NeurIPS 2025 D&B) shows some models' SWE-bench Verified performance "might be inflated" by contamination and provides a continuously refreshed task supply. — [SWE-rebench](https://proceedings.neurips.cc/paper_files/paper/2025/hash/21bec6ace947b1b58967b945c8ac0f10-Abstract-Datasets_and_Benchmarks_Track.html)

### Inferences
- For Ratchet, LoCoMo/LongMemEval-style scores are not a useful target: they test retrieval over a transcript, are near saturation, and have a documented ~6% label-noise floor and a lenient judge. The credible pattern in 2026 is a stream of verifiable tasks with a deterministic grader (Terminal-Bench 2 verifier, GDPevo code-based tests), a disjoint held-out split, and cost/latency reported alongside accuracy. Ratchet's SciFact read-only grader already matches this.
- Metrics worth adopting from the newer benchmarks: cumulative accuracy over the task stream (Evo-Memory), a forgetting-aware penalty for using invalidated memories (FAMA), a selective-forgetting / knowledge-update probe (MemoryAgentBench SF, STALE), abstention accuracy (LongMemEval), and an accuracy-vs-latency frontier (LongMemEval-V2 LAFS).
- Mem0's two-year drift from 66.88 to 92.5 on the same benchmark illustrates how heavily harness choices move scores; any Ratchet memory number should be reported with the full pipeline (ingestion, retrieval k, prompts, judge/grader, runs, std).

### Gaps
- No benchmark was found that specifically targets memory for scientific claim-verification agents (SciFact-like). The closest analogues are GDPevo (rule transfer with held-out recombination) and LongMemEval-V2 (environment "gotchas" and premise awareness).
- StructMemEval: no primary source was found under that name in this search; it may be a misremembered or very recent name. Not covered.
- LongMemEval-V2's public leaderboard shows "entries coming soon"; no third-party scores yet.

## Key Question 2: How do papers separate "memory helped" from "more context helped" or "model got lucky"? What statistical practices are used?

### Takeaway
The credible 2026 pattern is: paired memory-on/memory-off runs on the same task set, a compute- or token-matched long-context/RAG control, a zero-shot (no-history) control, a train/held-out split designed so test gains are attributable (and a third "gate" split if memory admission uses evaluation), multiple runs with power analysis (≈9 runs to detect a 2 pp effect at typical agent variance), clustered/paired standard errors, and explicit cost/latency accounting. Several papers additionally show that raw episodic logs are a necessary diagnostic baseline because consolidated memory can underperform them.

### Cited Findings

**Ablations and controls**

- Memory-on/off with causal attribution: Misevolution (ICLR 2026) ablates memory and finds "when the memory is removed, all models consistently achieve a 0% Unsafe Rate, in contrast to the high Unsafe Rate when memory is available," establishing memory as the causal factor. — [Misevolution, OpenReview rebuttal](https://openreview.net/forum?id=Fd1jgQQW28)
- Zero-shot control: MemoryAgentBench shows <4% without history vs 48.6% with it, to rule out pretraining knowledge as the source of "test-time learning." — [MemoryAgentBench appendix H](https://arxiv.org/html/2507.05257v4)
- Compute-matched control: MemoryAgentBench's "strict compute-matched comparisons" fix the token budget (~4K / ~40K / ~104K) across long-context, BM25 RAG, and an agentic memory system so retrieval vs. capacity effects are separable. — [MemoryAgentBench appendix J](https://arxiv.org/html/2507.05257v4)
- Episodic-only baseline: "Useful Memories Become Faulty" argues an episodic-only (raw trajectory) store "should be a diagnostic baseline" because "removing episodic evidence and using only abstract lessons collapses accuracy back to the no-memory baseline," i.e., the useful information lived in raw episodes, not distilled entries. — [arXiv 2605.12978](https://arxiv.org/html/2605.12978v1)
- Component ablation of a memory pipeline: the 3×3 study crossing write strategies and retrieval methods on LoCoMo finds retrieval method dominates (57.1% → 77.2%, a 20-point spread) while write strategy moves 3–8 points; failures "most often manifest at the retrieval stage rather than at utilization." — [Diagnosing Retrieval vs. Utilization Bottlenecks, arXiv 2603.02473](https://arxiv.org/abs/2603.02473)
- Intervention ablations: Proactive Memory Agent compares full memory agent vs exposing the full bank vs always-inject vs injection-only vs Mem0 on τ²-Bench (Sonnet baseline micro 55.0 → 61.2 full agent, 58.6 full-bank, 61.5 always-inject, 60.8 Mem0), showing "memory-style variants generally improve... but improvements are not equally robust across domains." — [arXiv 2607.08716](https://arxiv.org/html/2607.08716v1)
- Ordering controls: Evo-Memory tests Easy→Hard vs Hard→Easy task sequences and finds baseline methods vary substantially by order while evolving-memory agents are more stable, "highlight[ing] the importance of task sequence design for fair evaluation." — [Evo-Memory §4.2.3](https://arxiv.org/html/2511.20857v2)

**Held-out splits, leakage, and attribution**

- Three-way split with a dedicated gating split: "When Self-Evolution Backfires" splits Terminal-Bench 2 into Event (50, drives distillation), Holdout (14, used only for A/B replays inside admission gates), and Test (25, "never touched by distillation or gating"); it states "Event is the distillation split, [so] its numbers are an optimistic upper bound, whereas Test is the honest held-out estimate." Transfer is verified across five backbones and a second benchmark (InterCode NL2Bash: seed 57.5% → 69.0% with the frozen pool). — [arXiv 2608.05810](https://arxiv.org/html/2608.05810v1)
- GDPevo argues that "if the training and test tasks are identical or nearly identical, improvements may reflect memorization rather than generalization," so evolution-native benchmarks must construct train/test so acquired capabilities are "required and exercised" on test tasks; it lists controls that "distinguish transferable improvement from answer leakage, template reuse, scoring artifacts, and execution failures": designed train–test relationship, isolated information budgets, deterministic graders, calibration evidence, independent review, attempt-level traces; calibration runs use fresh agent processes that do not inherit the builder's context. — [GDPevo, arXiv 2608.03764](https://arxiv.org/html/2608.03764v1)
- EvoAgentBench uses a 528/267 train–test split "in which every test task has verified procedural support from the training tasks." — [cited in GDPevo §2.2.1](https://arxiv.org/html/2608.03764v1)
- RewardHackingAgents (2026) runs each episode in a fresh workspace with patch tracking and runtime file-access logging, compares agent-reported to true metrics, and defines "trust regimes" restricting access to held-out artifacts; it notes that if the evaluation pipeline is editable within the agent's workspace, the measured score can rise by editing the evaluator rather than improving the model. — [arXiv 2603.11337](https://arxiv.org/html/2603.11337v1)
- MemQ evaluates "generalization evaluation" (held-out tasks) separately from "runtime learning" across six benchmarks. — [MemQ, arXiv 2605.08374](https://arxiv.org/html/2605.08374v3)

**Statistical practice and noise bands**

- Agentic evals are noisy even at temperature 0: across 60,000 SWE-Bench-Verified trajectories, single-run pass@1 varies 2.2–6.0 pp depending on which run is picked, with std >1.5 pp; "reported improvements of 2–3 percentage points may reflect evaluation noise." Power table: detecting a 2 pp improvement at p<0.05 / 80% power needs ~9 runs per arm at σ=1.5%, 13 at σ=1.8%; 1 pp needs 36–51 runs; 5 pp needs 2–3. The paper recommends reporting pass@1, pass@k (optimistic) and pass^k (pessimistic). — [On Randomness in Agentic Evals, arXiv 2602.07150](https://arxiv.org/html/2602.07150v3)
- Anthropic's statistical guidance [older: Nov 2024]: compute standard errors via CLT; use paired differences when comparing two systems on the same questions (variance reduction when scores are correlated); cluster standard errors by question group — clustered SEs "can be over three times as large as naive standard errors"; reduce within-question variance by resampling. — [Anthropic, A statistical approach to model evals](https://www.anthropic.com/research/statistical-approach-to-model-evals); [Miller, Adding Error Bars to Evals](https://arxiv.org/pdf/2411.00640)
- "Measuring all the noises of LLM Evals" decomposes paired data noise vs prediction noise and argues leaderboards should release question-level results so third parties can compute significance. — [arXiv 2512.21326](https://arxiv.org/pdf/2512.21326)
- For K>2 systems on a shared eval, run an omnibus repeated-measures ANOVA or Friedman test before pairwise claims and correct for multiple comparisons. — [arXiv 2608.22659](https://arxiv.org/html/2608.22659v1)
- A practical protocol (MLflow, Jul 2026) recommends ≥3 seeds per configuration (5+ for publication), bootstrap 95% CIs, and variance decomposition; it cites a finding that 47% of score variance in one agent benchmark was seed noise. — [MLflow, Benchmarking AI Agent Performance](https://mlflow.org/articles/benchmarking-ai-agent-performance)
- Open tooling exists for Wilson/McNemar/cluster-bootstrap statistics, power analysis, sequential stopping, and Holm-corrected candidate elimination for agent evals; it cites "0.5–23.2% lucky passes" (tasks solved by trajectories that fail on re-run). — [evalsig](https://github.com/HZDF-2026/evalsig)
- Price-of-Safety's defense-cost study uses paired deltas vs an identical undefended baseline, three replicates, stratified bootstrap 95% CIs and McNemar tests, and tags every model call at a proxy by purpose so defense tokens are separable from baseline tokens; this per-purpose logging caught a pricing bug that had made reported costs wrong by 5×. — [arXiv 2609.22818](https://arxiv.org/pdf/2609.22818v1)

**Cost/latency accounting**

- MemoryAgentBench reports memory-construction and per-query latency per system (e.g., Mem0 10,804 s construction on MH-QA at 512-token chunks vs BM25 0.12 s; MIRIX 29,000 s). — [MemoryAgentBench appendix E.5](https://arxiv.org/html/2507.05257v4)
- MemoryArena finds external-memory agents "always incur the highest latency" and "no systematic relationship between memory operation complexity and execution latency." — [MemoryArena §4.5](https://arxiv.org/html/2602.16313v2)
- GDPevo reports one-time skill-generation overhead (USD, tokens) amortized across the five held-out tasks it serves. — [GDPevo appendix C](https://arxiv.org/html/2608.03764v1)
- Mem0's state-of-memory page reports tokens/query next to each score (e.g., 6,956 tokens/query on LoCoMo). — [Mem0 State of AI Agent Memory 2026](https://mem0.ai/blog/state-of-ai-agent-memory-2026)

### Inferences
- Ratchet already has a hidden held-out split and a measured noise band; the literature suggests adding a *third* split if memory admission is ever decided by evaluation (the VaG "Holdout" pattern), so the gate never sees the final test set and the memory never sees either.
- The minimum defensible report for "memory helped" on SciFact: paired memory-on vs memory-off on the same held-out claims, ≥9 runs per arm if the expected effect is ~2 pp (or fewer if the measured band is tighter), clustered SE by claim/paper, plus two controls: (i) a token-matched "dump recent raw episodes into context" baseline and (ii) a no-history zero-shot baseline. A gain only over (ii) but not (i) means "more context helped," not "memory helped."
- Report cumulative accuracy across the stream, not just the endpoint, because several papers show inverted-U trajectories where the endpoint hides a mid-stream peak.

### Gaps
- No paper was found that formally tests memory gains against a *noise band* measured from repeated memory-off runs in the way Ratchet does; the closest are power-analysis tables (2602.07150) and paired-bootstrap deltas (2609.22818).
- No source gave a standard for how many memory-write/consolidation cycles must elapse before reporting (the "cold start" issue noted by Evo-Memory's cumulative-accuracy curves).

## Key Question 3: What is the documented evidence that memory can hurt (noise, distraction, poisoning), and with what magnitude?

### Takeaway
Memory hurts in three documented ways with large effect sizes: (1) consolidation drift — continuously LLM-rewritten memories fall below the no-memory baseline (e.g., AWM on WebShop 0.64 → 0.20 as memory grows; GPT-5.4 fails 46–54% of ARC-AGI problems it had solved after consolidating ground-truth solutions); (2) skill/experience contamination — ungated accumulation peaks and then gives back most gains (Terminal-Bench 2: 62% → 50%), with post-hoc rollback recovering only ~17%; (3) poisoning — query-only injection reaches 98.2% injection and 76.8% attack success in MINJA's setting, 1.2% corpus poisoning drops LongMemEval accuracy 0.85 → 0.30, and memory evolution cuts refusal rates (46.3% → 11.9%). Realistic conditions (pre-existing legitimate memories) substantially reduce but do not eliminate poisoning.

### Cited Findings

**Noise, distraction, stale and contradictory memories**

- Consolidated memory degrades non-monotonically: "As consolidation proceeds, memory utility first rises, then degrades, and can fall below the no-memory baseline." On WebShop, AWM-distilled memory goes from 0.64 at 8 examples to 0.20 at 128 while no-memory sits at 0.20. On ScienceWorld, score peaks near step 20 and declines through step 100 for every memory size. — [Useful Memories Become Faulty, arXiv 2605.12978](https://arxiv.org/html/2605.12978v1)
- Cleanest case: GPT-5.4 solves a set of ARC-AGI problems at 100% without memory; after consolidating *from ground-truth solutions to those same problems*, it fails 46% of them (abstract states 54% on a set). Mechanisms: misgrouping before abstraction, overgeneralized lessons stripping applicability conditions, and overfitting to narrow streams (stable on exact repeats, collapses on simple variations). — [arXiv 2605.12978](https://arxiv.org/html/2605.12978v1)
- A single consolidation step collapsing 50 memory items into one "unified loop" cost 6–13 wins out of 48 across three Qwen3.5 sizes; under task switching, cumulative consolidation accumulates over-generalized memories at ~5× and garbage memories at ~20× the rate of fresh consolidation. Streamed incremental updates underperform a single whole-pool pass because "early abstractions can anchor later rewrites." — [arXiv 2605.12978, §4, §6, App. G/K](https://arxiv.org/html/2605.12978v1)
- Experience-following: "high similarity between a task input and the input in a retrieved memory record often results in highly similar agent outputs," producing two failure modes — error propagation (inaccurate past experiences compound) and misaligned experience replay (outdated/irrelevant experiences). A fixed-memory baseline sometimes beat runs guided by coarse evaluators, "indicating that noisy or low-quality" additions cause "self-degradation." — [How Memory Management Impacts LLM Agents, ACL 2026](https://aclanthology.org/2026.acl-long.27.pdf); [arXiv 2505.16067](https://arxiv.org/html/2505.16067v1)
- Evo-Memory: when both successful and failed experiences are stored unfiltered, "baseline methods suffer notable degradation... naive memory accumulation introduces noise and hinders retrieval." Several memory modules score below the no-memory baseline on single-turn reasoning (Claude 3.7 Sonnet: baseline 0.54 avg; LangMem 0.49; AWM 0.48; DC-Cu/DC-RS 0.52). — [Evo-Memory](https://arxiv.org/html/2511.20857v2)
- Context length alone hurts even with perfect retrieval: across 5 LLMs on math/QA/coding, performance degrades 13.9%–85% as input length increases "without any distraction," well within claimed context limits. — [Context Length Alone Hurts, EMNLP 2025 Findings](https://aclanthology.org/2025.findings-emnlp.1264/)
- RAG at high budget "saturates and slightly degrades (88.0) due to retrieved noise" vs 93.0 for long-context. — [MemoryAgentBench appendix J](https://arxiv.org/html/2507.05257v4)
- Stale memory reuse is pervasive: Memora's FAMA penalty produces "large score reductions" across all LLMs and memory agents, revealing "frequent reuse of invalid memories and failures to reconcile evolving memories." — [Memora, ACL 2026 Findings](https://aclanthology.org/2026.findings-acl.1337)
- MemoryAgentBench: all methods fail multi-hop selective forgetting (≤28%); a conservative update policy ("Policy B") lowered average performance by 4.5 points. — [MemoryAgentBench](https://arxiv.org/html/2507.05257v4); [OpenReview](https://openreview.net/forum?id=DT7JyQC3MR)
- Survey: "persistent retrieval of irrelevant or obsolete memories can disrupt the coherence in reasoning," and "unrestricted expansion of memory is detrimental." — [From Storage to Experience survey, ACL 2026 Findings](https://aclanthology.org/2026.findings-acl.2069.pdf)
- An untrained memory agent can hurt: a 27B memory agent without training "reduc[ed] SETA reward from 0.709 to 0.693"; SFT/GRPO recovered it. Memory "injection-only" without a bank *lowered* airline-domain pass@1 from 68.0 to 62.0. — [arXiv 2607.08716](https://arxiv.org/html/2607.08716v1)

**Contamination and overfitting of experience/skill memory**

- Terminal-Bench 2, ungated skill accumulation: seed 46% → 48% (R1, 35 skills) → 60% → 62% peak (R3, 105 skills) → 52% → 50% (R5, 179 skills), ending only 2 pp above R1. Hard-tier pass@1 erodes from 53% to 35%. Post-hoc removal of culprit skills recovers 1.7 pp of the 12.3 pp drop (oracle full-lineage cleanup 6.7 pp) because derived skills inherit flaws. — [When Self-Evolution Backfires, arXiv 2608.05810](https://arxiv.org/html/2608.05810v1)
- Overfit to the distillation split is explicitly modeled: Event-split numbers are "an optimistic upper bound." — [arXiv 2608.05810](https://arxiv.org/html/2608.05810v1)
- Misevolution (ICLR 2026): after memory evolution, refusal rate on RedCode-Gen dropped 46.3% → 11.9% and attack success rose 53.1% → 75.0% (Qwen2.5-72B); workflow evolution was worse (6.3% refusal, 83.8% ASR). Memory evolution showed *episodic* collapse: safety stable for 50 rounds, then a sudden drop after a high-satisfaction reward for an unreasonable refund created a flawed heuristic. Confabulation rose from 63.3% → 73.3% (Qwen3-Coder-480B) and 60.0% → 70.0% (GPT-4.1) after memory evolution. — [Misevolution, OpenReview](https://openreview.net/forum?id=Fd1jgQQW28); [arXiv 2509.26354](https://arxiv.org/abs/2509.26354)
- GDPevo case study "TG018: Negative Transfer from Dropped Scope Conditions": remembering an action without its jurisdiction/date/status conditions "produces confident negative transfer." — [GDPevo appendix F.3](https://arxiv.org/html/2608.03764v1)

**Poisoning and injection (academic)**

- AgentPoison (NeurIPS 2024 [older]): backdoor triggers optimized in embedding space; ≥80% attack success with <0.1% poison rate and ≤1% benign impact across a driving agent, QA agent, and EHRAgent. — [AgentPoison](https://proceedings.neurips.cc/paper_files/paper/2024/hash/eb113910e9c3f6242541c1652e30dfd6-Abstract-Conference.html)
- MINJA (NeurIPS 2025): attacker injects malicious records "solely through interacting with the agent via queries and output observations" using bridging steps, an indication prompt, and progressive shortening; 98.2% average injection success and 76.8% average attack success (>95% ISR and >70% ASR on most settings). — [MINJA, NeurIPS 2025](https://proceedings.neurips.cc/paper_files/paper/2025/file/42a97bbd9844d2bf68596730af80bcdf-Paper-Conference.pdf); [arXiv 2503.03704](https://arxiv.org/html/2503.03704)
- Replication under realistic conditions (Jan 2026, EHR agents on MIMIC-III): with empty initial memory, GPT-4o-mini ASR 62% / ISR 100%; with relevant pre-existing memories ASR 6.67% / ISR 26.67%. For Llama-3.1-8B, ISR stays ~99–100% but ASR drops from 52.94% to 0%, i.e., poison is stored but outvoted by correct examples. Raising retrieval k from 3 to 10 raises ASR back to 38% (GPT-4o-mini) / 27% (Llama). Best-case realistic ASR "as low as 38%... and 28%." — [Memory Poisoning Attack and Defense, arXiv 2601.05504](https://arxiv.org/html/2601.05504v2)
- Plain false assertions, no trigger optimization: poisoning 1.2% of a LongMemEval corpus reduces accuracy 0.850 → 0.300; a four-stage write-time screening pipeline with 0.832 recall on indirect prompt injection "rejects 0 of 360 poisoned memories." — [Utility Under Attack, arXiv 2608.21230](https://arxiv.org/abs/2608.21230)
- The EMNLP 2026 security survey organizes attacks across six lifecycle phases (WRITE, STORE, RETRIEVE, EXECUTE, SHARE & PROPAGATE, FORGET & ROLLBACK) and notes "the effective write-stage attack surface includes... any observable context that can influence what the agent decides to store." — [Survey on LTM Security, EMNLP 2026](https://aclanthology.org/2026.emnlp-main.2296.pdf)

**Poisoning and injection (incidents and PoCs on production systems)**

- ChatGPT memory, May 2024 [older]: Rehberger showed indirect prompt injection (website/doc) could write false memories and instructions into ChatGPT memory, creating persistence. — [Embrace The Red, Hacking Memories](https://embracethered.com/blog/posts/2024/chatgpt-hacking-memories)
- Jul 2024 [older]: persistent denial-of-service across sessions via injected memories; "Malicious memory modifications remain until the user manually removes the attacker-created memories." OpenAI initially classified it as a "model safety issue," not a security issue. — [Embrace The Red, Persistent DoS](https://embracethered.com/blog/posts/2024/chatgpt-persistent-denial-of-service)
- Sep 2024 [older] "SpAIware": prompt injection from a website persisted spyware instructions in ChatGPT macOS memory to continuously exfiltrate all future conversations via image-rendering URLs; OpenAI mitigated the exfiltration channel, but the author states memory-hacking via injection is "No[t]" fixed. — [Embrace The Red, SpAIware](https://embracethered.com/blog/posts/2024/chatgpt-macos-app-persistent-data-exfiltration); [Ars Technica](https://arstechnica.com/security/2024/09/false-memories-planted-in-chatgpt-give-hacker-persistent-exfiltration-channel)
- Feb 2025: delayed tool invocation bypassed Gemini's untrusted-data tool restrictions, resulting in "permanent planting of long-term memories." — [Ars Technica, Gemini long-term memory](https://arstechnica.com/security/2025/02/new-hack-uses-prompt-injection-to-corrupt-geminis-long-term-memory)
- Aug 2025: Windsurf Cascade's memory tool is invoked automatically without human approval; the author "had it happen a few times that a memory was added that I didn't catch right away," enabling SpAIware-style persistence. — [Embrace The Red, Windsurf](https://embracethered.com/blog/posts/2025/windsurf-spaiware-exploit-persistent-prompt-injection/)
- Aug 2025: a `url_safe` bypass allowed exfiltration of ChatGPT chat history and memories; root cause reported to OpenAI "over two years ago." — [Embrace The Red (archived)](https://web.archive.org/web/20250802191311/https://embracethered.com/blog/posts/2025/chatgpt-chat-history-data-exfiltration)
- Oct 2025: Unit 42 PoC on Amazon Bedrock Agents — indirect injection is stored during memory summarization and "Amazon Bedrock Agents automatically injects memory contents into every new session's context," so the payload activates in later sessions. — [Unit 42](https://unit42.paloaltonetworks.com/indirect-prompt-injection-poisons-ai-longterm-memory)
- Apr 2026: Cisco compromised Claude Code auto-memory via an npm postinstall hook that overwrote `~/.claude/projects/*/memory/MEMORY.md`, modified `~/.claude/settings.json` (UserPromptSubmit hook), and added a shell alias re-enabling auto-memory if disabled. The poisoned agent recommended committing API keys to source and advised against `.env`/env vars. Anthropic shipped a mitigation in Claude Code v2.1.50 removing user memories from the system prompt; Anthropic's stated position is that the user principal on the machine is fully trusted and users are responsible for vetting dependencies. — [Cisco Blogs](https://blogs.cisco.com/ai/identifying-and-remediating-a-persistent-memory-compromise-in-claude-code)
- A secondary source describes a CSRF flaw in ChatGPT Atlas's memory write path allowing a crafted URL to silently write attacker instructions into persistent memory. (Secondary source; primary LayerX report not retrieved.) — [aisec.blog](https://aisec.blog/posts/chatgpt-exploit)

### Inferences
- For Ratchet, the most relevant "memory hurts" evidence is not poisoning but drift: Ratchet's memory would be written by the agent from its own SciFact trajectories, which is precisely the regime where 2605.12978 and 2608.05810 show inverted-U curves and irreversible contamination. The practical implication is that every memory version must be evaluated on held-out claims before it replaces the previous one, and that a raw-episode store should be kept as a baseline/fallback.
- The confabulation increase (+10 pp) after memory evolution is a specific risk for a claim-verification agent: a memory of "papers in domain X usually SUPPORT" could become a prior that overrides evidence.
- Poisoning via SciFact abstracts is possible in principle (an abstract is untrusted text the agent reads and may summarize into memory), but the realistic-conditions replication suggests a store seeded with many correct memories dilutes single injections; the bigger risk is the leakage critic's domain — memories that encode test answers — rather than adversarial injection.

### Gaps
- No quantitative study was found on memory poisoning or drift specifically in scientific-QA / claim-verification agents.
- Primary LayerX source for the Atlas memory-CSRF was not retrieved; treat that incident as unverified here.
- Magnitudes for stale-memory harm in Memora/STALE are given as FAMA reductions and benchmark scores, not as a clean "accuracy lost to staleness" number across systems.

## Key Question 4: What concrete safeguards do production systems (Claude Code memory, ChatGPT memory, Mem0, Letta, Zep) apply to memory writes and reads, and what mitigations does the literature validate?

### Takeaway
Production systems in 2026 mostly provide *inspectability and user control* (view/edit/delete, project scoping, incognito/temporary modes, size caps, timestamps) and *write-time reconciliation* (Mem0's ADD/UPDATE/DELETE/NOOP decision, Zep's temporal invalidation with provenance), but few provide write authorization, rollback, or verified forgetting; the EMNLP 2026 survey rates Mem0 as having no support for write authorization, rollbackability, or verified forgetting. The research literature's strongest validated mitigation is *pre-commit gating with held-out behavioral replay* (VaG: 72% vs 50% pass@1, with holdout replay the single most important critic at −10 pp when removed). Content-only screening fails against plain false assertions, read-time reranking has a 33.6% false-quarantine rate on benign traffic, and provenance down-weighting has "no usable setting" when evidence itself arrives untrusted.

### Cited Findings

**Claude Code / Anthropic**

- Auto memory stores notes Claude writes itself in `~/.claude/projects/<project>/memory/` with a `MEMORY.md` index; the first 200 lines or 25KB of `MEMORY.md` are loaded at session start, and Claude Code warns/errs when the index exceeds limits. Memory files carry a `type` frontmatter field and Claude Code stamps a `modified` ISO-8601 timestamp so the age of a fact is visible to the user and to Claude. — [Claude Code memory docs](https://code.claude.com/docs/en/memory)
- Both CLAUDE.md and auto memory are "context, not enforced configuration. To block an action regardless of what Claude decides, use a PreToolUse hook instead." Managed settings (`permissions.deny`, sandbox) are enforced by the client; CLAUDE.md "is not a hard enforcement layer." — [Claude Code memory docs](https://code.claude.com/docs/en/memory)
- Controls: `/memory` browses/edits/deletes everything ("plain markdown"); auto memory can be disabled per user, per project (`autoMemoryEnabled: false`), or via `CLAUDE_CODE_DISABLE_AUTO_MEMORY=1`; it is off by default in self-hosted environments; memory is machine-local and not loaded into subagents (except forks); when `permissions.blockReadsOutsideWorkingDirectories` is on, no auto memory is loaded from or saved to a directory chosen by a repository-supplied settings file. `/doctor prompt-audit` checks instruction files for outdated or conflicting content. — [Claude Code memory docs](https://code.claude.com/docs/en/memory)
- After the Cisco disclosure, Claude Code v2.1.50 removed user memories from the system prompt so "memory files no longer have the same architectural authority over the model's core instructions." — [Cisco Blogs](https://blogs.cisco.com/ai/identifying-and-remediating-a-persistent-memory-compromise-in-claude-code)
- Anthropic's API memory tool is client-side: "Your application executes every file operation Claude requests, so these safeguards are your responsibility." Claude "usually refuses to write sensitive information to memory files. For stronger guarantees, add validation that strips sensitive data before your handler writes the file"; docs also recommend scoping instructions ("Only write down information relevant to <topic>"). — [Anthropic memory tool docs](https://docs.anthropic.com/en/docs/agents-and-tools/tool-use/memory-tool)
- Claude.ai memory is project-scoped, fully optional, viewable/editable, with incognito chats that don't save to memory; Anthropic says it ran safety testing on whether memory could reinforce harmful patterns. — [Anthropic, Bringing memory to teams](https://www.anthropic.com/news/memory)
- Claude Code security docs list network-command approval (curl/wget not auto-approved), network access controls, and retention limits as prompt-injection and privacy safeguards. — [Claude Code security docs](https://code.claude.com/docs/en/security?ref=groktop.us)

**ChatGPT / OpenAI**

- Users can view, edit, correct, or delete remembered information, use a non-personalized temporary chat, and turn Memory off; turning Memory off does not delete past chats and re-enabling may recreate memories from history; "Sensitive information can appear in Memory if you share it"; limited safety/security uses of context persist even with Memory off. — [OpenAI Memory FAQ](https://help.openai.com/en/articles/8590148-memory-faq-)
- OpenAI fixed the SpAIware exfiltration channel after disclosure but the injection-to-memory write path itself is reported as unfixed. — [Embrace The Red, SpAIware](https://embracethered.com/blog/posts/2024/chatgpt-macos-app-persistent-data-exfiltration)

**Mem0**

- Pipeline: `add` extracts candidate facts, looks up related memories, and an LLM selects one of ADD / UPDATE / DELETE / NOOP ("not a similarity threshold but an LLM-selected operation"); memories are scoped by `user_id`, `agent_id`, `run_id`, metadata; the application decides which retrieved memories enter the prompt; explicit `update`/`delete` exist and can be tied to thumbs up/down feedback; immutable memories must be deleted and re-added. Mem0 also recommends relevance-score decay (access resets, disuse lowers) and write-time contradiction checks against top similar memories, with recency sort as a read-time backstop. — [Mem0, How it works](https://docs.mem0.ai/core-concepts/how-it-works); [Mem0 update op](https://docs.mem0.ai/core-concepts/memory-operations/update); [Mem0, Memory eviction and forgetting](https://mem0.ai/blog/memory-eviction-and-forgetting-in-ai-agents)
- Governance assessment: "Mem0 provides no support for WA [write authorization], RB [rollbackability], or VF [verified forgetting]. It offers partial support for PV [provenance visibility], reflected in its change-history tracking... and partial support for PS [principal-scoped retrieval]." — [EMNLP 2026 survey](https://aclanthology.org/2026.emnlp-main.2296.pdf)

**Zep**

- Temporal knowledge graph: on contradiction Zep "records which episode did the" invalidation; "an invalidated fact stays in the graph with its full history rather than being deleted"; facts keep a growing association set to source episodes; deleting an episode removes exactly what derived from it ("if three conversations independently established the same relationship, deleting one of them must not remove" it); provenance is evaluated at query time to scope retrieval by source attributes. — [Zep, How Zep tracks provenance](https://blog.getzep.com/how-zep-tracks-provenance-in-agent-memory); [Zep concepts](https://help.getzep.com/v2/concepts)
- Zep docs advise sending retrieved memory text "through the provider's untrusted-data channel so it cannot override your agent's" instructions rather than as system/developer messages. — [Zep concepts](https://help.getzep.com/v2/concepts)

**Letta**

- Memory blocks are explicit, described, inspectable units; "Share read-only policies across all agents from a central source." Letta Code stores memory in MemFS, a git-backed memory filesystem with version history, conflict resolution, and direct editing; agents can update memory on their own or via `/remember`; sleep-time/"dream" subagents review conversations and write lessons. — [Letta memory blocks](https://docs.letta.com/guides/core-concepts/memory/memory-blocks/index.md); [Letta Code memory](https://docs.letta.com/letta-code/memory/index.md)

**Research-validated mitigations**

- Pre-commit gating (VaG): every distilled skill starts "Cold" (recorded, invisible); Gate 1 requires passing a deterministic schema check, a single-skill A/B replay on held-out tasks, and one LLM semantic review; Gate 2 is marginal-gain greedy selection on joint held-out performance (k=3 replays); only "Hot" skills reach the runtime context; rejected skills never enter the next round's distillation context. Result: 72% pass@1 vs 50% ungated at R5 with a 5× smaller pool. Ablation: −holdout replay −10 pp, −marginal-gain gate −8 pp (pool 37 → 58), −semantic check −4 pp, −schema −2 pp. — [arXiv 2608.05810](https://arxiv.org/html/2608.05810v1)
- Gate abstraction rather than force it: policies that gate consolidation ("Auto") or keep an episodic-only store "match or exceed forced abstraction," so "mandatory rewriting at every step — rather than abstraction itself" is the failure mode. — [arXiv 2605.12978](https://arxiv.org/html/2605.12978v1)
- Memory sanitization with trust scores + temporal decay + retrieval-time threshold: on GPT-4o-mini the configuration was so conservative it rejected all 23 candidate memories (benign included); on Gemini-2.0-Flash, 54 of 82 accepted entries (score 1.0) were actually poison, so "once a poison entry successfully deceives the model into assigning high trust, retrieval-time filtering becomes ineffective without secondary verification." — [arXiv 2601.05504](https://arxiv.org/html/2601.05504v2)
- Content-only screening cannot catch plain false assertions (0/360 rejected); additive provenance penalties have "no usable setting" — a weight strong enough to resist query-shaped poison also suppresses legitimate untrusted evidence (evidence recall → 0, accuracy 0.0417 when answer-bearing evidence is untrusted); the paper argues for bounded occupancy constraints at retrieval (cap the fraction of context from untrusted sources) instead. — [Utility Under Attack, arXiv 2608.21230](https://arxiv.org/abs/2608.21230)
- Benign-case cost of defenses: three write-time defenses (lexical sanitization, provenance tagging, LLM anomaly detection) show no resolvable utility cost (95% CIs ±~4.5 pp incl. zero) and 0% false quarantine; the read-time reranker costs −4.4 pp accuracy (95% CI [−9.0, −0.05]) and quarantines 33.6% of legitimate memories on attack-free traffic (up to 106 in one conversation) at 2.7% token overhead; stacking all four did not compound cost. Conclusion: "Where a defense intercepts the pipeline, not whether it uses an LLM, appears to determine its benign-case price." — [The Price of Safety, arXiv 2609.22818](https://arxiv.org/pdf/2609.22818v1)
- A-MemGuard: consensus validation across related memories plus a separate "lesson memory" of detected failures consulted before acting; ASR reduced by >60% (final avg 0.256 GPT-4o-mini, 0.233 Llama-3.1-8B); without lesson memory ASR climbs to 78% over rounds (self-reinforcing trap) vs ~13–15% with it. — [A-MemGuard, arXiv 2510.02373](https://arxiv.org/pdf/2510.02373); [OpenReview](https://openreview.net/forum?id=fVxfCEv8xG)
- MemSentry intercepts proposed memory writes and emits deterministic Accept / Review / Quarantine decisions using source trust, semantic risk, attack radius over a component-dependency DAG, access risk, and a signed security-state delta; 91.7% accuracy, 0.908 macro-F1; dangerous writes are escalated for human review rather than auto-quarantined. — [MemSentry, arXiv 2609.08747](https://arxiv.org/abs/2609.08747v1)
- Misevolution mitigations are partial: a prompt-based memory safety check did not reduce SWE-Bench performance; a post-evolution safety node moved ASR 83.8% → 73.1% and refusal 6.3% → 17.0%. — [Misevolution, OpenReview](https://openreview.net/forum?id=Fd1jgQQW28)
- Verifiable Memory Governance (VMG) primitives with proposed metrics: Write Authorization (adaptive injection-survival rate at bounded FPR), Provenance Visibility (fraction of entries traceable to source event through summarization/merging), Principal-Scoped Retrieval, Rollbackability (versioned snapshots + write logs to restore a known-safe state), Verified Forgetting (post-deletion membership tests across raw logs, summaries, indices, copies). The survey argues security "must be anchored in storage-time provenance, versioning, auditability, and policy-aware retention, rather than retrofitted only at retrieval or execution time," and cites VerificAgent's human-verified freeze and MemOS's MemCube metadata (source, version, sensitivity, time) as write-time exemplars. — [EMNLP 2026 survey](https://aclanthology.org/2026.emnlp-main.2296.pdf)
- Industry guidance converges on the same list: Microsoft recommends treating "memory writes as privileged operations," source approval, provenance tracking, integrity checks, versioning, change review, rollback, periodic refresh, domain isolation, and trust scoring. OWASP runs an "Agent Memory Guard" project that screens every memory operation through detectors and a declarative policy. WorkOS recommends quarantine-not-delete for forensics, `derivedFrom` provenance to build dependency graphs, auditing every decision made during the exposure window, and monitoring drift in the distribution of retrieved memory sources. — [Microsoft Learn](https://learn.microsoft.com/en-us/security/zero-trust/catalog-ai-attack-techniques/ai-memory-context-poisoning); [OWASP Agent Memory Guard](https://owasp.org/www-project-agent-memory-guard); [WorkOS](https://workos.com/blog/ai-agent-memory-poisoning)
- Reflecting the "store rather than rewrite" result, ACE (Agentic Context Engineering) avoids "context collapse" with structured, incremental updates instead of monolithic rewrites, reporting +10.6% on agent benchmarks. — [ACE, arXiv 2510.04618](https://arxiv.org/abs/2510.04618)

### Inferences
- A Ratchet memory design consistent with the evidence: (1) append-only episodic store with provenance (`derivedFrom` claim IDs, source abstract IDs, run ID, timestamp) and no automatic consolidation; (2) distilled "lessons" enter a Cold tier and are promoted only after a paired A/B replay on a *gate* split (not the hidden test split) shows non-negative effect within the noise band; (3) read-time: bounded occupancy (cap tokens from memory) rather than similarity-ranked dumps, plus a hard filter on the leakage critic's rules; (4) versioned snapshots of the memory directory per promotion so rollback to the last known-good state is one operation; (5) human review for anything that would alter the agent's *decision rule* (e.g., label priors) rather than its procedural knowledge.
- Expect write-time filters to be cheap in benign utility but weak against false assertions; expect read-time rerankers to silently drop a third of legitimate memories. Ratchet's grader-based gate (behavioral replay) is the one mitigation with strong evidence, and it is already the kind of machinery Ratchet has.

### Gaps
- No vendor (Anthropic, OpenAI, Mem0, Letta, Zep) publishes a quantitative evaluation of its memory-write safeguards against injection (ASR, false-positive rates). All production claims here are architectural descriptions.
- Letta's MemFS/git-backed memory would appear to satisfy rollbackability, but no independent assessment was found.

## Key Question 5: How is memory leakage of test items (an agent memorizing benchmark answers) detected or prevented?

### Takeaway
No paper was found that proposes a dedicated "memory leakage critic" for self-improving agents; the field prevents leakage structurally — disjoint distillation/gate/test splits, information budgets, fresh workspaces with file-access logging, refreshable task supplies — and detects it indirectly through transfer tests (performance on a second benchmark or backbone) and by flagging memories that are stable on exact repeats but collapse on variations. Ratchet's leakage critic is ahead of the published state of practice.

### Cited Findings

- Structural prevention via splits: Test (25 tasks) "never touched by distillation or gating"; frozen skill pool evaluated on a second benchmark (InterCode) and four other backbones "to verify the learned skills do not overfit this split." — [arXiv 2608.05810](https://arxiv.org/html/2608.05810v1)
- GDPevo: "If the training and test tasks are identical or nearly identical, improvements may reflect memorization rather than generalization"; it uses rule hybridization so test tasks recombine rules, "isolated information budgets," deterministic graders, independent review, and attempt-level traces to separate "transferable improvement from answer leakage, template reuse, scoring artifacts." Its automated pipeline regenerates the suite (120 → 240 tasks "within two days") as a "practical response to contamination." — [GDPevo](https://arxiv.org/html/2608.03764v1)
- Runtime detection of held-out access: RewardHackingAgents logs runtime file access and patch history per episode and detects "leakage (accessing held-out data or labels during training)," defining trust regimes that restrict training-time access to held-out artifacts; it warns that an editable evaluation pipeline lets agents raise scores by editing the evaluator. — [arXiv 2603.11337](https://arxiv.org/html/2603.11337v1)
- Behavioral signature of memorization: in ARC-AGI streams, overfit memory keeps "performance... stable on exact repetitions of those problems but collapses on simple variations within the same strategy family." — [arXiv 2605.12978 §6.3](https://arxiv.org/html/2605.12978v1)
- Zero-shot/no-history control as a contamination check: MemoryAgentBench shows <4% without history, arguing results are not from pretraining knowledge. — [MemoryAgentBench appendix H](https://arxiv.org/html/2507.05257v4)
- Benchmark-level contamination: SWE-rebench builds a continuously refreshed, decontaminated task set and finds some models' SWE-bench Verified scores "might be inflated." Mem0 acknowledges LoCoMo and LongMemEval have been public long enough that contamination is a concern. — [SWE-rebench](https://proceedings.neurips.cc/paper_files/paper/2025/hash/21bec6ace947b1b58967b945c8ac0f10-Abstract-Datasets_and_Benchmarks_Track.html); [Mem0, How to Read Memory Benchmarks](https://mem0.ai/library/agent-memory/how-to-read-memory-benchmarks)
- Provenance as a leakage-audit substrate: VMG's Provenance Visibility requires "lineage-complete provenance... through any intermediate summarization or merging steps," which is what would let an auditor trace a memory back to the task that produced it. — [EMNLP 2026 survey](https://aclanthology.org/2026.emnlp-main.2296.pdf)

### Inferences
- Ratchet's existing critic (rejecting edits that encode test items) generalizes to memory if every memory entry carries `derivedFrom` claim IDs: any entry whose lineage touches a held-out claim ID is rejected at write time, and entries whose text has high lexical/semantic overlap with a held-out claim or its gold evidence are quarantined for review. This is the Write Authorization + Provenance Visibility pair from VMG, applied to leakage rather than injection.
- Add the behavioral test from 2605.12978: periodically evaluate the memory on paraphrased/perturbed versions of training claims; a large gap between exact-repeat and perturbed accuracy is the signature of memorized items rather than transferable procedure.
- Because consolidation can launder provenance (a summary of ten episodes loses the IDs), either forbid consolidation of entries with mixed splits or require the consolidator to carry the union of source IDs, as Zep does with association sets.

### Gaps
- No published metric or tool specifically for "memory encodes benchmark answers" was found; detection in the literature is indirect (transfer, perturbation, provenance audit).
- No source quantifies how often self-improving agents' memories end up containing verbatim test items in practice.
