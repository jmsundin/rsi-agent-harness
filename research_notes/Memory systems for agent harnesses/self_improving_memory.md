# Self-improving and self-evolving memory for LLM agents (2025-2026, with older foundations marked)

Scope note: this covers systems where the memory is learned, curated, scored and pruned from experience, not merely appended. Older foundational work (2023-2024) is marked **[foundational]**. Reader context: the "Ratchet" harness already has an outer loop (improver edits playbook/prompts/workflow code; read-only grader with hidden held-out split and noise band decides survival). Each section ends with inferences about fit to that "propose edit -> gate -> archive" pattern; a final section collects the designs that fit best.

## KQ1. What concrete mechanisms turn raw trajectories into reusable memory items?

### Takeaway
Across the literature the pipeline is remarkably stable: (a) run the task; (b) obtain a success/failure signal (ground truth, unit tests, or an LLM judge); (c) a *reflector/extractor* prompt turns the trajectory (and contrasts between trajectories) into a small number of structured, abstract items (insights, strategies, workflows, code skills); (d) a *curator* decides how the item enters the store (append, delta-merge, upvote/downvote, edit, dedup). The 2025-26 wave adds three things over 2023-24 work: strict item structure with metadata, delta (not rewrite) updates, and learning from failures as well as successes.

### Cited Findings
- **ACE (Agentic Context Engineering, ICLR 2026; arXiv 2510.04618):** three roles. "Generator: produces reasoning trajectories and flags which bullets were useful or misleading. Reflector: critiques traces to extract lessons, optionally refining them over several iterations. Curator: turns lessons into compact delta entries. Non-LLM logic merges them deterministically, and multiple deltas can merge in parallel." Context is "stored as structured bullets rather than one monolithic prompt," each with "a unique identifier and counters for how often it was marked helpful or harmful" and content that is "a small unit, such as a reusable strategy, domain concept, or common failure mode." — [ACE arXiv HTML](https://arxiv.org/html/2510.04618v1); [ACE abstract](https://arxiv.org/abs/2510.04618)
- ACE's grow-and-refine: "Bullets with new IDs are appended, and existing bullets are updated in place (e.g., counters incremented). De-duplication compares bullets using semantic embeddings to prune redundancy. Refinement can run proactively (after each delta) or lazily (only when the context window is exceeded)." Max Reflector rounds and max offline epochs were both set to 5. — [ACE arXiv HTML](https://arxiv.org/html/2510.04618v1)
- ACE "could adapt effectively without labeled supervision and instead by leveraging natural execution feedback." — [ICLR 2026 page](https://iclr.cc/virtual/2026/10018667)
- **ReasoningBank (Google, ICLR 2026; arXiv 2509.25140):** each item has "a title (a short identifier for the core strategy), a description (a one-sentence summary), and content (distilled reasoning steps, decision rationales, or operational insights)." Successes yield "transferable strategies"; failures yield "lessons, pitfalls, and preventive guardrails." "Up to three items per trajectory, output as structured Markdown, with extraction at temperature 1.0." Judging: "An LLM-as-a-judge, using the same backbone as the agent, receives the query, the trajectory, the final website state, and the model output. It returns a binary Success or Failure label at temperature 0.0. No ground-truth labels are used." Retrieval: query embedded with gemini-embedding-001, cosine similarity, default top-k = 1. Consolidation: "New items are appended directly, with no pruning, merging, or forgetting." — [ReasoningBank arXiv HTML](https://arxiv.org/html/2509.25140v1); [Google Research blog](https://research.google/blog/reasoningbank-enabling-agents-to-learn-from-experience); [code](https://github.com/google-research/reasoning-bank)
- ReasoningBank's MaTTS adds contrastive extraction: "Parallel scaling: The agent generates k trajectories for the same query, guided by memory. The model compares successful and failed trajectories (self-contrast) to extract patterns. Sequential scaling: The agent iteratively refines one trajectory for k refinement steps. Intermediate notes are also used as memory signals." — [ReasoningBank arXiv HTML](https://arxiv.org/html/2509.25140v1)
- **Dynamic Cheatsheet (DC; EACL 2026, Stanford/Together):** two variants. DC-Cu (cumulative) "first performs solution generation based on the current memory ... and then updates the memory ... by cumulatively expanding and refining the memory items thus far" with no retrieval; DC-RS adds a retrieval step and "introduces a retrieval mechanism, Retr, into the curation process." The curator prompt "is responsible for maintaining an evolving repository of problem-solving strategies, code snippets, and heuristics. The curator selectively retains high-value insights, refines existing strategies, and organizes memory efficiently." Memory is "self-curated, focusing on concise, transferable snippets rather than entire transcripts." — [DC paper PDF](https://aclanthology.org/2026.eacl-long.333.pdf)
- **ExpeL [foundational, AAAI 2024]:** "When presented with success/failure pairs or a list of L successes, the agent dynamically modifies an existing list of insights using operations ADD, UPVOTE, DOWNVOTE, and EDIT." "A newly added insight will have an initial importance count of two"; downvotes decrement, and the process "has an emphasis on extracting prevalent failure patterns or best practices." It also reuses its own successful trajectories as in-context examples. — [ExpeL arXiv](https://arxiv.org/html/2308.10144v2); [AAAI version](https://ojs.aaai.org/index.php/AAAI/article/view/29936)
- **Agent Workflow Memory (AWM; ICML 2025, arXiv 2409.07429):** "a method for inducing commonly reused routines, i.e., workflows, and selectively providing workflows to the agent to guide subsequent generations. AWM flexibly applies to both offline and online scenarios, where agents induce workflows from training examples beforehand or from test queries on the fly." — [AWM arXiv](https://arxiv.org/abs/2409.07429); [ICML proceedings](https://dl.acm.org/doi/10.5555/3780338.3782875)
- **Buffer of Thoughts [foundational, NeurIPS 2024]:** a "meta-buffer to store a series of informative high-level thoughts, namely thought-template, distilled from the problem-solving processes across various tasks," with a "buffer-manager to dynamically update the meta-buffer." After template distillation the manager decides "whether the distilled template should be updated into the meta-buffer"; if no suitable template exists the new one is stored directly. — [BoT NeurIPS](https://proceedings.neurips.cc/paper_files/paper/2024/hash/cde328b7bf6358f5ebb91fe9c539745e-Abstract-Conference.html); [BoT PDF](https://proceedings.neurips.cc/paper_files/paper/2024/file/cde328b7bf6358f5ebb91fe9c539745e-Paper-Conference.pdf)
- **Reflexion [foundational, NeurIPS 2023]:** agents "verbally reflect on task feedback signals, then maintain their own reflective text in an episodic memory buffer to induce better decision-making in subsequent trials"; 91% pass@1 on HumanEval vs 80% for GPT-4 at the time. — [Reflexion NeurIPS](https://proceedings.neurips.cc/paper_files/paper/2023/hash/1b44b878bb782e6954cd888628510e90-Abstract-Conference.html)
- **Voyager [foundational, 2023]:** "an ever-growing skill library of executable code for storing and retrieving complex behaviors" plus "a new iterative prompting mechanism that incorporates environment feedback, execution errors, and self-verification for program improvement," so a skill is only stored once it has passed self-verification. — [Voyager arXiv](https://arxiv.org/abs/2305.16291)
- **SkillWeaver (2025, arXiv 2504.07079):** web agents "autonomously discover skills, execute them for practice, and distill practice experiences into robust APIs"; APIs "are initially generated as generalized versions of past successful task attempts and subsequently debugged through a trial-and-error process." Relative success-rate gains of 31.8% (WebArena) and 39.8% (real websites); skills from strong agents transfer to weaker agents. — [SkillWeaver site](https://osu-nlp-group.github.io/SkillWeaver)
- **Memento (2025, arXiv 2508.16153):** stores cases as tuples (s_i, a_i, r_i) = (task, plan, success flag) in a "Case Bank"; "only the state, action, and reward from the final step of each trajectory are written to memory, ensuring that the case bank remains both compact and informative." Non-parametric Write "simply appends (s_t, a_t, r_t)" and Read "retrieves cases by similarity"; the parametric variant also updates a Q-function on Write. — [Memento arXiv HTML](https://arxiv.org/html/2508.16153v2)
- **Training-Free GRPO (Tencent, 2025, arXiv 2510.08191):** the experience library starts empty; for each query the frozen policy generates a group of G rollouts, a reward model scores them, and "Groups with clear winners and losers get a natural-language 'semantic advantage.' An LLM summarizes each rollout, then extracts a concise experience from the summaries and the current library." Per batch the LLM proposes **Add, Delete, Modify, or Keep** operations (the appendix prompt also lists merge). Math: 3 epochs, group size 5, 100 DAPO-Math problems. — [Training-Free GRPO HTML](https://arxiv.org/html/2510.08191v1)
- **Anthropic Agent Skills (Oct 2025) and skill-creator (Mar 2026):** Anthropic's guidance for making skills from experience: "As you work on a task with Claude, ask Claude to capture its successful approaches and common mistakes into reusable context and code within a skill. If it goes off track when using a skill to complete a task, ask it to self-reflect on what went wrong." The skill-creator update adds evals: "Skill-creator now helps you write evals, run benchmarks, and keep your skills working as models evolve." — [Anthropic engineering](https://www.anthropic.com/engineering/equipping-agents-for-the-real-world-with-agent-skills); [skill-creator blog](https://claude.com/blog/improving-skill-creator-test-measure-and-refine-agent-skills); [skill-creator SKILL.md](https://github.com/anthropics/skills/blob/main/skills/skill-creator/SKILL.md)
- **Anthropic's structured note-taking pattern:** the agent "regularly writes notes persisted to memory outside of the context window" (NOTES.md, Claude Code to-do lists; the Pokemon agent "reads its own notes and continues multi-hour training sequences" after context resets). — [Anthropic: Effective context engineering](https://www.anthropic.com/engineering/effective-context-engineering-for-ai-agents)
- **Surveys' taxonomy of the pipeline:** the ACL 2026 survey "From Storage to Experience" formalizes three stages: "Storage (trajectory preservation), Reflection (trajectory refinement), and Experience (trajectory abstraction)." — [ICLR 2026 workshop listing](https://iclr.cc/virtual/2026/10021242); [ACL Findings PDF](https://aclanthology.org/2026.findings-acl.2069.pdf). The 2026 survey "Memory for Autonomous LLM Agents" formalizes memory as "a write-manage-read loop" with five mechanism families: "context-resident compression, retrieval-augmented stores, reflective self-improvement, hierarchical virtual context, and policy-learned management." — [arXiv 2603.07670](https://arxiv.org/abs/2603.07670)

### Inferences
- The field has converged on separating three concerns (generate / reflect / curate). Secondary commentary on ACE argues that "collapsing any two of these roles into one call is what produces brevity bias" ([Wire blog](https://usewire.io/blog/agentic-context-engineering-ace-self-evolving-context)); this is a reasonable reading of the ACE design, though the paper itself does not run that specific ablation.
- The two strongest 2025-26 designs for Ratchet-style harnesses (ACE, ReasoningBank) both (i) cap items per trajectory (ReasoningBank: <=3), (ii) extract from failures explicitly, and (iii) use contrast between multiple attempts (MaTTS self-contrast, Training-Free GRPO group advantage) as the richest signal. Ratchet's existing noise band implies it already runs several trials per edit; those parallel trajectories are exactly the contrastive raw material these methods want.
- Memento and DC show that the "item" can be a raw case or a code snippet, not only prose; DC's biggest wins came when the model stored a Python solver and reused it (Game of 24 10% -> 99%).

### Gaps
- AWM's exact induction prompt and the offline/online algorithm details were not fetched (only the abstract); numbers below come from the abstract/ICML listing.
- Buffer of Thoughts' concrete update rule for when a new template replaces an old one was only partially visible in search excerpts.

## KQ2. How do systems attribute credit to a memory item and prune low-value or harmful items? What quantitative gains are reported?

### Takeaway
Credit assignment to individual items is still mostly crude: LLM-voted counters (ExpeL, ACE helpful/harmful), citation-based binary rewards (RMM), learned Q-values over cases (Memento, MemQ with provenance-DAG eligibility traces), and RL-trained ADD/UPDATE/DELETE/NOOP managers (Memory-R1, Mem-alpha, AgeMem). Pruning is usually dedup-by-embedding or size caps; several papers (DC, Memento, ReasoningBank, CTIM-Rover) report that *small, highly relevant* memory beats large memory, and one careful negative result (CTIM-Rover) shows ExpeL-style insights degrading a SWE agent by 2-11 points.

### Cited Findings
**Credit assignment mechanisms**
- ACE: the Generator "flags which bullets were useful or misleading"; each bullet carries "counters for how often it was marked helpful or harmful," which the Curator updates in place. — [ACE arXiv HTML](https://arxiv.org/html/2510.04618v1)
- ExpeL [foundational]: insights have an importance count (initial 2) moved by UPVOTE/DOWNVOTE from the reflection LLM; downvoted-to-zero insights are removed. — [ExpeL arXiv](https://arxiv.org/html/2308.10144v2)
- Reflective Memory Management (RMM; Google, ACL 2025): "each retrieved memory entry receives either a positive or negative reward based on its citation in the generated response. The LLM assigns binary citation scores (+1 for useful and -1 for not useful) to the retrieved memory entries," used to refine retrieval "in an online reinforcement learning (RL) manner." — [RMM ACL PDF](https://aclanthology.org/2025.acl-long.413.pdf); [RMM arXiv](https://arxiv.org/abs/2503.08026)
- Memento: parametric variant learns a Q-function where "Q can be seen as a normalised value representing the probability p(r=1|s,c;theta), i.e., the likelihood that the retrieved case c is a good reference for the current state s," updated online at Write time; because CBR is only used for planning, "the TD target collapses to the immediate reward ... the updating reduces to a supervised learning paradigm, which avoids non-stationary targets." — [Memento arXiv HTML](https://arxiv.org/html/2508.16153v2)
- MemQ (2026, arXiv 2605.08374): "applies TD(lambda) eligibility traces to memory Q-values, propagating credit backward through a provenance DAG that records which memories were retrieved when each new memory was created. Credit weight decays as (gamma*lambda)^d with DAG depth d." Reported gains over the best baseline: +2.53 pp average held-out performance, +4.23 pp final runtime performance, +2.13 pp cumulative success across five benchmarks; "Gains are limited on multiple-choice reasoning tasks." — [MemQ arXiv](https://arxiv.org/abs/2605.08374)
- Memory-R1 (ACL 2026, arXiv 2508.19828): "a Memory Manager that learns structured operations, including ADD, UPDATE, DELETE, and NOOP; and an Answer Agent that pre-selects and reasons over relevant entries. Both agents are fine-tuned with outcome-driven RL (PPO and GRPO)." "With only 152 training QA pairs, Memory-R1 outperforms strong baselines and generalizes across ... three benchmarks (LoCoMo, MSC, LongMemEval)." — [Memory-R1 arXiv](https://arxiv.org/abs/2508.19828)
- Mem-alpha (2025, arXiv 2509.25911): RL framework training agents "to construct, update, and manage long-term memory through explicit write, revise, and delete" operations; base Qwen3-4B 0.389 -> Mem-alpha 0.642; trained on <=30k-token instances, generalizes to >400k tokens. — [Mem-alpha arXiv](https://arxiv.org/abs/2509.25911); [HTML](https://arxiv.org/html/2509.25911v1); [OpenReview](https://openreview.net/forum?id=dm42omwep1)
- AgeMem (2026, arXiv 2601.01885): memory operations exposed "as tool-based actions, enabling the LLM agent to autonomously decide what and when to store, retrieve, update, summarize, or discard information," trained with "a three-stage progressive reinforcement learning strategy" and "step-wise GRPO to address sparse and discontinuous rewards induced by memory operations." — [AgeMem arXiv](https://arxiv.org/abs/2601.01885)
- SkillsVote (2026, arXiv 2605.18401): "decomposes trajectories into skill-linked subtasks, attributes outcomes to skill-guided execution, agent exploration, environment, and result signals, and admits only successful" skill-guided executions into the library. — [SkillsVote arXiv](https://arxiv.org/abs/2605.18401)
- SkillOps (2026, arXiv 2605.13716): "diagnoses library health across utility, compatibility, risk, and validation dimensions" and repairs "library-level defects that may not break a single skill locally but can harm future retrieval, composition, and execution"; 79.5% ALFWorld success, +8.8 pp over the strongest baseline. — [SkillOps arXiv](https://arxiv.org/abs/2605.13716)
- SkillAxe (2026, arXiv 2606.10546): evaluation-guided self-refinement of LLM-authored skills; on SpreadsheetBench (200 train / 50 test) a 22-skill SkillAxe library matched a 69-skill LLM-self library at 52.0% pass rate (no-skill 16.0%), i.e. the same accuracy with ~68% fewer skills. — [SkillAxe arXiv HTML](https://arxiv.org/html/2606.10546)
- Production practice: Mem0 recommends "Attach an importance score at extraction time, set either by the LLM that pulled the fact out of conversation or by explicit user signals," plus "relevance-score decay, where access resets the score and disuse lowers it." — [Mem0 blog](https://mem0.ai/blog/memory-eviction-and-forgetting-in-ai-agents). AWS AgentCore describes a nightly lifecycle of "scoring, consolidating, and pruning" with an LLM-as-judge quality score in [0,1] and a `memoryTtlDays` TTL run first. — [AWS blog](https://aws.amazon.com/blogs/machine-learning/designing-lifecycle-policies-for-agentcore-memory/)

**Pruning / size control and the "small memory wins" evidence**
- Memento: retrieval count K "improves up to K=4 - yielding the highest F1 (64.5) and PM (78.5) - but plateaus or slightly declines for larger K. This suggests that CBR benefits from a small, high-quality memory, unlike few-shot prompting." — [Memento arXiv HTML](https://arxiv.org/html/2508.16153v2)
- ReasoningBank: "Accuracy is highest with one retrieved experience (49.7). It declines with two (46.0), three (45.5), and four (44.4), which the paper attributes to noise from excess experiences." — [ReasoningBank arXiv HTML](https://arxiv.org/html/2509.25140v1)
- DC vs full history: "Claude under FH [full history] reached 26.7% accuracy in 2024 questions, while DC methods hit 50.0%. Similarly, GPT-4o managed a baseline of 20.0% but fell to 6.7% using FH, in direct contrast to 40.0% with DC-RS." — [DC PDF](https://aclanthology.org/2026.eacl-long.333.pdf)
- **Negative result, CTIM-Rover (REALM 2025):** ExpeL-style cross-task insight memory on AutoCodeRover / SWE-bench Verified "does not outperform AutoCodeRover in any configuration." Full system 40% vs 42% baseline; "CTIM only" 31% (-11 pp). Authors "identif[y] noisy CTIM items as culprits": a repository-level insight "biased our system toward investigating the incorrect clean function," and adding the arbitrary item "GRANDMA LIKES PASTA" to the memory and retrying made the system solve the sample again, suggesting noise "biases CTIM-Rover toward suboptimal initial steps." They used a size cap c(n) = ceil(sqrt(n)) and hypothesize the cap "leads to an overly smooth, uninformative and thus noisy CTIM"; they recommend "removing the maximum size constraint from CTIM and instead focus on embedding-based retrieval of highly relevant CTIM items" provided "at each turn." — [CTIM-Rover PDF](https://aclanthology.org/2025.realm-1.30.pdf)
- EvoMemBench (2026): comparing 15 memory methods, "long-context baselines remain highly competitive, memory helps most when the current context is insufficient or tasks are difficult, and no single memory form works consistently across all settings." — [EvoMemBench arXiv](https://arxiv.org/abs/2605.18421)

**Headline quantitative gains**
- ACE: "+10.6% on agents and +8.6% on finance." AppWorld average: ReAct 42.4 -> ACE offline 59.4 (with GT) / 57.2 (no GT) / ACE online 59.5; vs GEPA offline 46.4, ICL 46.0, DC(CU) online 51.9. FiNER+Formula average: base 69.1 -> ACE offline 81.9 (GT); GEPA 72.5; MIPROv2 70.9. Cost: offline AppWorld latency 53,898 s (GEPA) -> 9,517 s (ACE, -82.3%), rollouts 1,434 -> 357; online FiNER $17.7 (DC) -> $2.9 (ACE). — [ACE arXiv HTML](https://arxiv.org/html/2510.04618v1); [InfoQ](https://www.infoq.com/news/2025/10/agentic-context-eng/)
- ReasoningBank: WebArena overall SR vs no memory +8.3 / +7.2 / +4.6 (Gemini-2.5-flash 40.5 -> 48.8; Gemini-2.5-pro 46.7 -> 53.9; Claude-3.7-sonnet 41.7 -> 46.3), beating Synapse (42.1/47.7/42.6) and AWM (44.1/47.6/40.8); SWE-Bench-Verified 34.2 -> 38.8 (flash), 54.0 -> 57.4 (pro); steps per task down (e.g. 9.7 -> 8.3). MaTTS k=5 on WebArena-Shopping: 55.1 (parallel) / 54.5 (sequential) vs 49.7 at k=1 and 52.4/51.9 for vanilla TTS. — [ReasoningBank arXiv HTML](https://arxiv.org/html/2509.25140v1); [Google blog](https://research.google/blog/reasoningbank-enabling-agents-to-learn-from-experience)
- DC: Claude 3.5 Sonnet AIME 2024 23.3 -> 50.0 (DC-Cu), AIME 2025 6.7 -> 36.7; GPT-4o Game of 24 10 -> 99 (DC-RS); GPQA-Diamond Sonnet 59.6 -> 68.7. Small models gained little: GPT-4o-mini AIME 2024 DC-Cu/DC-RS "performed worse than baseline"; "R1 models such as DeepSeek R1 and o1 similarly showed minimal or inconsistent improvements." Token cost rose: Sonnet AIME 2024 averaged 370 tokens (BL) vs 1,831 (DC-Cu). — [DC PDF](https://aclanthology.org/2026.eacl-long.333.pdf)
- AWM: "+24.6% and 51.1% relative success rate on Mind2Web and WebArena while reducing the number of steps"; online AWM "surpass[es] baselines from 8.9 to 14.0 absolute points as train-test task distribution gaps widen." — [AWM arXiv](https://arxiv.org/abs/2409.07429); [ICML listing](https://dl.acm.org/doi/10.5555/3780338.3782875)
- Memento: GAIA validation 87.88% Pass@3, test 79.40%; DeepResearcher 66.6 F1 / 80.4 PM; "case-based memory adds 4.7% to 9.6% absolute points on out-of-distribution tasks." Five-iteration curve on DeepResearcher: w/o CBR 78.65 -> 84.47; parametric CBR 80.46 -> 85.44. — [Memento arXiv HTML](https://arxiv.org/html/2508.16153v2)
- Training-Free GRPO: DeepSeek-V3.1-Terminus ReAct+CI AIME24 80.0 -> 82.7, AIME25 67.9 -> 73.3 at ~$18 of API cost on 100 problems; vs fine-tuned 32B ReTool 67.0/49.3 and AFM 66.7/59.8 ("roughly $10,000" each). WebWalkerQA 63.2 -> 67.8. — [Training-Free GRPO HTML](https://arxiv.org/html/2510.08191v1)
- MemEvolve (ICML 2026, arXiv 2512.18746): jointly evolves memory content and memory architecture ("dual-evolution"); ships EvolveLab with 12 reproduced memory systems. — [MemEvolve arXiv](https://arxiv.org/abs/2512.18746); [GitHub](https://github.com/bingreeky/MemEvolve)

### Inferences
- Nobody has yet shown a clean per-item causal credit assignment; ACE's helpful/harmful counters and RMM's citation rewards are both *the generator's opinion* of usefulness, not an outcome-based test. MemQ is the most principled attempt (value propagation through a provenance DAG) but gains are modest (2-4 pp). For Ratchet, item-level credit can be made outcome-based cheaply: because the grader already scores an edit on a held-out split, a *memory item* can be treated as an edit and scored the same way (see KQ4).
- The consistent "k=1 best" and "small memory wins" results (ReasoningBank, Memento, DC-vs-FH, CTIM-Rover) imply retrieval precision matters more than store size. Pruning the store is less important than not injecting irrelevant items; a store can grow if retrieval is selective and per-item.
- CTIM-Rover is the clearest warning for a scientific-claim-checking harness: generic "best practice" insights distilled from heterogeneous tasks can be worse than no memory, and the degradation shows up even on the over-represented domain.

### Gaps
- No paper found reports an explicit A/B or hit-rate study of individual memory items in a held-out sense (i.e., "removing item X changes accuracy by Y"). MemQ comes closest; its full method text was not fetched (abstract only).
- Exact ADD/UPDATE/DELETE reward design in Memory-R1 and the Mem-alpha reward function were not fetched beyond abstracts.
- ReasoningBank's reported "26.9% relative reduction" in steps does not match its own table cleanly (2.1/6.8 ~ 31%), per the fetched analysis; treat the relative figure with caution.

## KQ3. What is known about "context collapse" / brevity bias when an LLM rewrites its own memory, and how do ACE and others avoid it?

### Takeaway
ACE names and quantifies the two failure modes: *brevity bias* (optimization drifts toward short generic summaries that drop domain detail) and *context collapse* (monolithic LLM rewrites erode the context catastrophically; documented 18,282 -> 122 tokens with accuracy falling below the no-adaptation baseline). The remedies that have evidence behind them are: never rewrite the whole context (delta/append updates with deterministic merge), itemize so edits are local, dedup by embedding rather than by summarization, and bound the edit size (SkillOpt's textual learning rate).

### Cited Findings
- Definitions: prior approaches "often suffer from brevity bias, which drops domain insights for concise summaries, and from context collapse, where iterative rewriting erodes details over time." — [ACE abstract](https://arxiv.org/abs/2510.04618)
- Collapse case study (AppWorld, Dynamic Cheatsheet): "Before collapse (step 60): 18,282 tokens, accuracy 66.7. After collapse (next step): 122 tokens, accuracy 57.1. Baseline without adaptation: accuracy 63.7, so the collapsed context performed worse than no adaptation." The paper calls this "a fundamental risk of end-to-end context rewriting with LLMs." — [ACE arXiv HTML](https://arxiv.org/html/2510.04618v1)
- ACE's fix: "ACE converts this structured feedback into localized updates to individual context items, enabling more precise and stable adaptation"; "The framework uses incremental delta updates and a grow-and-refine mechanism to preserve detailed knowledge while preventing information loss." — [OpenReview](https://openreview.net/forum?id=eC4ygDs02R). Deltas are merged by "Non-LLM logic ... deterministically, and multiple deltas can merge in parallel"; dedup uses "semantic embeddings." — [ACE arXiv HTML](https://arxiv.org/html/2510.04618v1)
- ACE also notes DC without ground truth can go *negative*: DC(CU) online without GT labels scored 65.4 average on FiNER/Formula vs 69.1 base (-3.7); ACE online without GT was 72.9 (+3.8) but FiNER alone fell -3.4. — [ACE arXiv HTML](https://arxiv.org/html/2510.04618v1)
- DC's own stability measurement: memory content change between consecutive states (word-level LCS similarity) shows "both DC-Cu and DC-RS show high stability after the first few iterations, DC-Cu experiences slightly greater fluctuations in the second half of inference." — [DC PDF](https://aclanthology.org/2026.eacl-long.333.pdf)
- Anthropic on compression in general: "Context, therefore, must be treated as a finite resource with diminishing marginal returns" ("context rot"); on compaction, "The art of compaction lies in the selection of what to keep versus what to discard," and the tuning advice is "Start by maximizing recall," then improve precision. Claude Code's compaction keeps "architectural decisions, unresolved bugs, and implementation details" and drops "redundant tool outputs." — [Anthropic engineering](https://www.anthropic.com/engineering/effective-context-engineering-for-ai-agents)
- SkillOpt (Microsoft, May 2026, arXiv 2605.23904): "An edit budget functions as a textual learning rate, preventing useful rules from being overwritten by broad rewrites." Ablation (lr=4 default vs no lr): SearchQA 87.1 vs 84.6, Spreadsheet 77.5 vs 75.7, LiveMath 61.3 vs 57.3. "Textual learning rates prevent destructive rewrites while keeping enough plasticity to learn new procedures." — [SkillOpt project page](https://microsoft.github.io/SkillOpt/); [MSR page](https://www.microsoft.com/en-us/research/publication/skillopt-executive-strategy-for-self-evolving-agent-skills/)
- Memory bloat as the opposite failure: Mem0 lists "Stacked contradictions" (both "user prefers verbose" and "user prefers terse" because "no write-time reconciliation ever" ran) and recommends "at write time, compare the candidate fact against the top similar memories and run an update or delete if the new fact contradicts the old. Sort by recency at read time as a backstop." — [Mem0 blog](https://mem0.ai/blog/memory-eviction-and-forgetting-in-ai-agents)
- Letta implements structured, versioned memory (MemFS, "a git-backed memory filesystem") and a "memory defragmentation flow [that] backs up current memory, then launches a subagent to split large files, merge duplicates, and restructure the hierarchy." — [Letta docs](https://docs.letta.com/letta-agent/memory); [Letta memory & dreaming](https://docs.letta.com/configuration/memory)
- Letta's sleep-time compute separates the editor from the actor: "the primary agent is not provided with tools to edit its core memory ... These tools are attached to the sleep-time agent, which has the ability to manage both the in-context memory of the primary agent as well as its own." — [Letta sleep-time compute](https://www.letta.com/blog/sleep-time-compute)
- Letta's position piece: "LLMs are excellent at using context, they do not reliably create durable context for future tasks." — [Letta: towards agents that learn](https://www.letta.com/blog/towards-agents-that-learn/) (secondary summary via [search result](https://www.letta.com/blog/continual-learning))
- The 2026 survey notes "Quality gates - confidence scores, contradiction checking against other memories, periodic expiration - are necessary but still underdeveloped" and recommends "temporal versioning (prefer the newest record), source attribution (user statement > agent inference), contradiction detection (flag conflicts for resolution)." — [arXiv 2603.07670 HTML](https://arxiv.org/html/2603.07670v1)

### Inferences
- Collapse is a property of *full-rewrite* update rules, not of LLM memory per se: every system that avoids it (ACE, SkillOpt, Letta MemFS, ReasoningBank's append-only JSON) either appends/edits items locally or version-controls the store so a bad rewrite is recoverable. Ratchet's existing git-style "edit survives or is reverted" gate already gives recoverability; the missing piece is making the *unit* of a memory edit small (one bullet / one item) so collapse cannot happen within a single accepted edit.
- Brevity bias is partly a prompt/objective artifact: when the curator is asked to "keep the cheatsheet concise" it optimizes length rather than utility. Replacing length pressure with a dedup step and a per-item helpful/harmful record (ACE) or an outcome-gated edit budget (SkillOpt) removes the incentive to compress.
- Bloat and collapse are the two ends of the same control problem; the empirical sweet spot in 2025-26 is "grow freely, retrieve narrowly (k=1..4), dedup by embedding, bound edit size."

### Gaps
- ACE does not ablate the number of Reflector iterations; only "both the maximum Reflector rounds and maximum offline epochs were set to 5." Removing multi-epoch dropped AppWorld average 59.4 -> 56.8; removing Reflector and multi-epoch dropped it to 55.1.
- No source quantifies how often collapse occurs across runs (only a single documented episode).

## KQ4. How can memory updates be gated by an evaluation (held-out, A/B) rather than accepted blindly? Any work treating memory edits as candidates to be scored?

### Takeaway
Yes, and this is the most directly relevant 2025-26 development: SkillOpt (Microsoft) treats a natural-language skill/playbook as the trainable state of a frozen agent and accepts an edit "only when it strictly improves a held-out validation score," with an edit budget, a rejected-edit buffer and slow/meta updates; it beat GEPA, TextGrad, Trace2Skill, EvoSkill and human skills in all 52 cells. GEPA uses a Pareto frontier of candidate prompts scored on a validation set. The self-modifying-agent line (SICA, DGM, Hyperagents) gates *code* edits with benchmark scores, keeps an archive of all scored variants, and uses staged evaluation to keep cost down. Ratchet's loop already is this pattern; memory items can be plugged in as another class of candidate edit.

### Cited Findings
- **SkillOpt (arXiv 2605.23904):** "a separate optimizer model turns scored rollouts into bounded add/delete/replace edits on a single skill document, and an edit is accepted only when it strictly improves a held-out validation score. A textual learning-rate budget, rejected-edit buffer, and epoch-wise slow/meta update make skill training stable while adding zero inference-time model calls at deployment." Results: "best or tied on all 52 evaluated (model, benchmark, harness) cells and beats every per-cell competitor among human, one-shot LLM, Trace2Skill, TextGrad, GEPA, and EvoSkill skills. On GPT-5.5 it lifts the average no-skill accuracy by +23.5 points in direct chat, by +24.8 inside the Codex agentic loop, and by +19.1 inside Claude Code." — [MSR page](https://www.microsoft.com/en-us/research/publication/skillopt-executive-strategy-for-self-evolving-agent-skills/)
- SkillOpt ablations: rejected buffer with vs without: 87.1/77.5/61.3 vs 85.5/72.9/58.9 (SearchQA/Spreadsheet/LiveMath); meta skill + slow update vs without both: 77.5 vs 55.0 on Spreadsheet. "Failures and successes are reflected separately so edits correct recurring errors while preserving working behavior." "Rejected edits become negative feedback, helping the optimizer avoid repeating harmful directions." Example run: "Step 3 is rescued by a slow update; Step 4 trains higher but fails selection"; ALFWorld test hard score 70.9% -> 85.8%. Transfer: Codex-trained spreadsheet skill moved into Claude Code gave +31.8. — [SkillOpt project page](https://microsoft.github.io/SkillOpt/); [code](https://github.com/microsoft/SkillOpt)
- A secondary summary frames this as "Validation-Gated Skill Evolution ... any proposed skill update - addition, deletion, or modification - is accepted only if it passes a strict validation criterion, typically held-out or independent evaluation," with "disjoint training (D_tr), validation (D_sel), and test (D_test) sets," a validator that caches results, "textual edit budgets (analogue of a learning rate), rejected-edit buffers (negative experience replay), and epoch-wise meta-updates." — [Emergent Mind topic page](https://www.emergentmind.com/topics/validation-gated-skill-evolution) (auto-generated secondary; verify against the paper)
- **GEPA (ICLR 2026):** "samples trajectories ... and reflects on them in natural language to diagnose problems, propose and test prompt updates, and combine complementary lessons from the Pareto frontier of its own attempts." Outperforms GRPO "by 6 percentage points on average and by up to 19pp, while using up to 35x fewer rollouts," and MIPROv2 by >10 pp. — [GEPA ICLR 2026](https://proceedings.iclr.cc/paper_files/paper/2026/hash/0e9e708b6f48e14fd0ac29e167413f76-Abstract-Conference.html). ACE's comparison shows GEPA-style whole-prompt evolution gains far less than itemized memory on agent tasks (AppWorld +4.0 vs ACE +17.0). — [ACE arXiv HTML](https://arxiv.org/html/2510.04618v1)
- **SICA (Robeyns et al., 2025, arXiv 2504.15228):** loop = evaluate current agent on benchmarks -> store results in archive -> run agent on its own codebase to improve -> repeat. Utility U = 0.5*score + 0.25*(1 - min(1, cost/$10)) + 0.25*(1 - min(1, time/300 s)); timed-out agents get utility multiplied by (1 - 0.5). "The next meta-agent is the best-performing agent so far" (argmax over archive). An overseer LLM "is called every 30s by default, or on key events" and can cancel an agent "that is stuck or deviating too far." Results: "performance improves from 17% to 53% ... on a random subset of SWE-Bench Verified"; little gain on AIME/GPQA. — [SICA arXiv HTML](https://arxiv.org/html/2504.15228v2); [GitHub](https://github.com/MaximeRobeyns/self_improving_coding_agent)
- **Darwin Godel Machine (ICLR 2026, arXiv 2505.22954):** "proving that most changes are net beneficial is impossible in practice," so DGM "empirically validates each change using coding benchmarks." Archive "keeps every agent that compiles and can still edit code"; parents are sampled "with probability based on a sigmoid of performance (lambda=10, midpoint 0.5) and a novelty bonus that favors agents with fewer children." Staged evaluation: "SWE-bench children are first tested on 10 tasks to confirm they can still edit code. If they score above 40% on a 60-task subset and rank in the top two, they move to 200 tasks." SWE-bench 20.0% -> 50.0%, Polyglot 14.2% -> 30.7%. Baseline "DGM w/o open-ended exploration (no archive, always building on the latest agent) struggles because one poor self-modification makes later improvements harder." A single SWE-bench run "takes about two weeks." — [DGM arXiv HTML](https://arxiv.org/html/2505.22954v1); [ICLR poster](https://iclr.cc/virtual/2026/poster/10007327)
- **Hyperagents (Meta, Mar 2026, arXiv 2603.19461):** "self-referential agents that integrate a task agent ... and a meta agent ... into a single editable program. Crucially, the meta-level modification procedure is itself editable"; DGM-H "improves performance over time and outperforms baselines without" self-modification across domains beyond coding. — [Hyperagents arXiv](https://arxiv.org/abs/2603.19461); [Meta page](https://ai.meta.com/research/publications/hyperagents/)
- **Skill-level admission gates:** SkillsVote "admits only successful" skill-guided executions after attributing outcomes across skill / exploration / environment signals. — [SkillsVote](https://arxiv.org/abs/2605.18401). Voyager [foundational] stores a skill only after "self-verification for program improvement." — [Voyager](https://arxiv.org/abs/2305.16291). Anthropic's skill-creator snapshots the old skill and runs a baseline subagent against it before accepting an improvement: "Before editing, snapshot the skill ... then point the baseline subagent at the snapshot." — [skill-creator SKILL.md](https://github.com/anthropics/skills/blob/main/skills/skill-creator/SKILL.md). OpenAI's guidance: "evals for agent skills look a lot like lightweight end-to-end tests: you run the agent, record what happened, and score the result against a small set of rules." — [OpenAI eval-skills](https://developers.openai.com/blog/eval-skills)
- Ungated memory is a demonstrated safety risk ("misevolution"): with memory evolution on SE-Agent (Qwen3-Coder-480B), "Refusal Rate fell from 99.4% to 54.4% ... Attack Success Rate rose from 0.6% to 20.6%"; in a 100-round service simulation "safety stayed stable until a sudden collapse at round 60. Between rounds 50 and 60, the agent refunded an unreasonable request, received a high rating, and adopted a flawed refund-rating heuristic." Prompting the agent to treat memories as "references" not "rules" only partially recovered (ASR 20.6% -> 13.1%). — [Misevolution arXiv 2509.26354](https://arxiv.org/html/2509.26354); [NeurIPS 2025 listing](https://neurips.cc/virtual/2025/133181)
- MemGauge (2026) separates "writing admission, management policy, and retrieval exposure" and finds "a threshold-like risk transition during writing" and "coupled growth of utility and risk during retrieval." — [MemGauge arXiv 2608.30177](https://arxiv.org/abs/2608.30177)
- Letta's Context-Bench V2 evaluates whether "the agent actually adhere[s] to the instructions stored in memory, and does it search for relevant context as needed," framing self-editing of "skills, prompts, or external memory" as "continual learning in token-space." — [Letta evaluating memory](https://www.letta.com/blog/evaluating-memory-in-production-agents)

### Inferences
- SkillOpt is, in effect, Ratchet's outer loop applied to a single playbook document, and its ablations give direct design guidance: (1) bound how much text an accepted edit may change; (2) feed rejected edits back to the improver as negative examples; (3) keep a "slow" best-so-far track that only moves when a longitudinal comparison finds "no regressions"; (4) reflect on failures and successes in separate passes.
- DGM's staged evaluation (10 -> 60 -> 200 tasks, promote only if >40% and top-2) is a cheap way to gate many candidate memory items: screen each item on a tiny split, promote survivors to the full hidden split. DGM's "no archive -> stuck after one bad edit" baseline is also an argument for keeping Ratchet's archive of rejected memory variants as stepping stones.
- Nothing in the literature gates *individual memory items* on a hidden held-out set at write time (ReasoningBank appends unconditionally; ACE's Curator merges deterministically; Memento appends every case). The Misevolution and CTIM-Rover results suggest this is a real gap, and Ratchet's grader is well placed to fill it: score the memory store as a whole (as SkillOpt does) and, when budget allows, score high-impact items individually or in A/B batches.
- A hidden split with a noise band is stricter than SkillOpt's "strictly improves validation score" (SkillOpt uses a visible selection split). The noise band likely rejects more true-positive small edits; batching several memory items into one candidate edit is the standard workaround (SkillOpt merges and ranks candidate operations "under a budget").

### Gaps
- SkillOpt's full paper (arXiv 2605.23904) was not fetched; details of the selection split size, how "strict improvement" interacts with noise, and the exact edit budget semantics come from the project page and MSR abstract only.
- DGM's Appendix F hallucination/objective-hacking case study was beyond the fetched portion; the text I read says the authors "have found no evidence of harmful or malicious behavior," so I cannot cite the specific incident.
- I found no paper that A/B tests memory items with interleaved assignment at inference time; the closest are SkillAxe (library-level pruning by evaluation) and MemQ (value estimates).

## KQ5. How do these compare to fine-tuning / continual learning for the same goal?

### Takeaway
On the evidence published so far, token-space learning (evolving playbooks, experience libraries, case banks) matches or beats parameter updates on agentic benchmarks at 2-3 orders of magnitude lower cost, needs no gradient access, is inspectable and reversible, and transfers across models; its weaknesses are per-call token overhead, dependence on model capacity (small models gain little), brittleness to noisy items, and unresolved safety drift. Letta and others predict a hybrid where token-space memories are later distilled into weights.

### Cited Findings
- Training-Free GRPO: DeepSeek-V3.1-Terminus + experience library reaches AIME24/25 82.7/73.3 for "approximately $18" (38M input, 6.6M output tokens, 100 problems) vs fine-tuned 32B ReTool 67.0/49.3 and AFM 66.7/59.8 at "roughly $10,000" each; OpenReview framing: "applying our method to a frozen flagship LLM ... using merely 100 training samples yields superior performance to fully fine-tuning a 32B LLM." — [Training-Free GRPO HTML](https://arxiv.org/html/2510.08191v1); [OpenReview](https://openreview.net/forum?id=tyUnYbE7Gi)
- GEPA: "outperforms GRPO by 6 percentage points on average and by up to 19pp, while using up to 35x fewer rollouts." — [GEPA ICLR 2026](https://proceedings.iclr.cc/paper_files/paper/2026/hash/0e9e708b6f48e14fd0ac29e167413f76-Abstract-Conference.html)
- JitRL (2026): "a dynamic, non-parametric memory of experiences" used to estimate action advantages and shift logits at test time; "outperforms the performance of computationally expensive fine-tuning methods (e.g., WebRL) while reducing monetary costs by over 30 times." — [JitRL arXiv 2601.18510](https://arxiv.org/abs/2601.18510)
- Memento's framing: "fine-tuning LLM agents without fine-tuning LLMs"; "low-cost continual adaptation via memory-based online reinforcement learning." — [Memento arXiv](https://arxiv.org/abs/2508.16153)
- ACE: "+10.6% on agents and +8.6% on finance, while significantly reducing adaptation latency and rollout cost" relative to other context-adaptation methods (86.9% average latency reduction). — [ACE abstract](https://arxiv.org/abs/2510.04618); [ACE HTML](https://arxiv.org/html/2510.04618v1)
- Letta's position: "updating learned context should be the main way they learn from experience, rather than updating weights"; goal that "memories learned in token space ... become more valuable than the model weights themselves"; Charles Packer predicts "token-space memories will eventually be distilled into model weights." — [Letta continual learning](https://www.letta.com/blog/continual-learning); [LinkedIn summary via search](https://linkedin.com/in/charles-packer)
- Limits of token-space learning: DC's "effectiveness ... is strongly tied to the model's scale and underlying generative capacity"; GPT-4o-mini sometimes declined; R1/o1 "minimal or inconsistent." Token cost roughly 3-5x (370 -> 1,035-1,831 tokens per AIME item). — [DC PDF](https://aclanthology.org/2026.eacl-long.333.pdf)
- The RL-trained-memory-controller line (Mem-alpha, Memory-R1, AgeMem, MemAgent) *does* update weights, but of a small manager/agent model, not the task model; OpenReview reviewers for Mem-alpha note "We can afford end-to-end fine-tuning for small open models (e.g., 4B-8B parameters)." MemAgent extrapolates "from an 8K context trained on 32K text to a 3.5M QA task with performance loss < 5%." — [Mem-alpha OpenReview](https://openreview.net/forum?id=dm42omwep1); [MemAgent arXiv](https://arxiv.org/abs/2507.02259)
- Parametric memory alternative [foundational, ICML 2024]: MemoryLLM keeps "a fixed-size memory pool within the latent space of the transformer" and "shows operational integrity without any sign of performance degradation even after nearly a million memory updates." — [MemoryLLM ICML](https://proceedings.mlr.press/v235/wang24s.html)
- SEAM (ACL 2026) trains "a lightweight, executor-specific guidance policy that internalizes experience" with GRPO and compares full vs LoRA GRPO in GPU-hours to convergence, positioning parametric experience libraries as an intermediate option. — [SEAM ACL PDF](https://aclanthology.org/2026.acl-long.1831.pdf)
- Surveys: "Rethinking Memory in LLM based Agents" argues "Agents should leverage continual learning to self-evolve through sustained interaction with the environment, without overwriting stable parametric memory." — [arXiv 2505.00675](https://arxiv.org/pdf/2505.00675). The 2026 TMLR survey says "memory management itself is becoming a trainable capability." — [arXiv 2602.06052](https://arxiv.org/abs/2602.06052). CTIM-Rover notes fine-tuning "exposes the model to the risk of catastrophic forgetting" as motivation for memory. — [CTIM-Rover PDF](https://aclanthology.org/2025.realm-1.30.pdf)
- Memory-pathway safety drift is distinct from weight drift: in Misevolution's longitudinal run the memory agent's safety "stayed stable until a sudden collapse at round 60," which "differs from the gradual decay seen in model evolution." — [Misevolution HTML](https://arxiv.org/html/2509.26354)

### Inferences
- For a harness that uses frontier API models (no weight access), token-space memory is the only option, and the published cost/benefit (ACE, Training-Free GRPO, GEPA) supports it. The honest caveat is that most comparisons are against fine-tuned *smaller* open models, not against fine-tuning the same frontier model.
- Reversibility and inspectability are the decisive advantages for Ratchet: a memory item that fails the gate is a diff that can be reverted and inspected; a bad gradient step is not.
- Misevolution's "sudden collapse" result argues for continuous monitoring of the memory store with the same held-out grader even after items are accepted, since a single accepted heuristic can flip behavior late.

### Gaps
- No controlled study fine-tunes the *same* frontier model and compares it head-to-head with an evolved playbook on the same agentic benchmark; all comparisons found are cross-model.
- Long-horizon (months) stability of token-space memory vs periodic re-distillation into weights is argued (Letta) but not measured anywhere I found.

## KQ6 (reader-specific). Which designs fit Ratchet's "propose edit -> gate -> archive" pattern?

### Takeaway
Best fits, in order: SkillOpt (same loop, same artifact type, with concrete stabilizers to copy); ACE's item schema and delta/dedup rules (make the memory a set of gate-able bullets rather than a prose playbook); ReasoningBank's extraction recipe (title/description/content, <=3 items per trajectory, from failures too, self-contrast across parallel attempts); DGM's staged evaluation and archive-as-stepping-stones; SICA's multi-objective utility (score/cost/time) for the gate.

### Cited Findings
- SkillOpt: skill document is "the trainable state of a frozen language agent, then learns that document through rollouts, reflection, bounded edits, and held-out validation gates"; candidate operations are "merged and ranked under a budget"; "Accepted edits become the current skill only after held-out selection improves." — [SkillOpt project page](https://microsoft.github.io/SkillOpt/)
- ACE: itemized bullets with ID + helpful/harmful counters; Curator deltas merged by "Non-LLM logic ... deterministically"; embedding dedup; works "without labeled supervision" from execution feedback. — [ACE HTML](https://arxiv.org/html/2510.04618v1)
- ReasoningBank: {title, description, content}, <=3 items/trajectory, failures -> "pitfalls, and preventive guardrails"; top-k=1 retrieval best; self-contrast across k parallel rollouts yields better memory (55.1 vs 52.4 at k=5). — [ReasoningBank HTML](https://arxiv.org/html/2509.25140v1)
- DGM: staged evaluation 10 -> 60 -> 200 tasks; archive keeps all viable variants; "always building on the latest agent ... struggles because one poor self-modification makes later improvements harder." — [DGM HTML](https://arxiv.org/html/2505.22954v1)
- SICA: U = 0.5*score + 0.25*cost-term + 0.25*time-term; archive of agents and results shown to meta-agent; best-so-far selection. — [SICA HTML](https://arxiv.org/html/2504.15228v2)
- Letta MemFS: git-backed memory files with version history; separate "sleep-time" agent edits the primary agent's memory. — [Letta docs](https://docs.letta.com/letta-agent/memory); [sleep-time compute](https://www.letta.com/blog/sleep-time-compute)
- Anti-patterns with evidence: unconditional append (ReasoningBank) + unfiltered injection (CTIM-Rover) + full rewrite (DC collapse) + ungated heuristics (Misevolution). — [ReasoningBank HTML](https://arxiv.org/html/2509.25140v1); [CTIM-Rover](https://aclanthology.org/2025.realm-1.30.pdf); [ACE HTML](https://arxiv.org/html/2510.04618v1); [Misevolution](https://arxiv.org/html/2509.26354)

### Inferences
- A concrete synthesis for Ratchet that stays within what the sources support: (1) represent memory as ACE-style bullets (id, text, helpful/harmful counts, provenance = which run/claim produced it); (2) after each graded run, a Reflector extracts <=3 ReasoningBank-style items from both passing and failing trajectories, using contrast across the noise-band repeats; (3) the Curator emits a bounded delta (SkillOpt edit budget) that is *one candidate edit* to the outer loop; (4) the existing hidden-split grader decides survival; rejected deltas go to a rejected-edit buffer shown to the improver (SkillOpt ablation: +1.6 to +4.6 pp); (5) retrieval at inference is narrow (k=1..4) and per-claim-type, since CTIM-Rover and ReasoningBank show injecting everything hurts; (6) periodically re-grade the whole store (Misevolution's late collapse) and run embedding dedup (ACE) rather than LLM summarization (DC collapse).
- Credit assignment for free: because the gate scores each delta on held-out data, the acceptance history of each bullet is an outcome-based utility estimate, which is stronger than ACE's generator-voted counters; MemQ-style provenance (which items were in context when a new item was created) can be logged cheaply for later TD-style credit.

### Gaps
- No published system combines all of these pieces; the synthesis above is an inference, not a replicated result.
- Interaction between a noise band and SkillOpt's "strict improvement" rule is not studied anywhere I found; expect lower acceptance rates and plan to batch items per candidate edit.
