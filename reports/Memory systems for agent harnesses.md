# Ratchet Should Gate Memory Like Code

The state of the art in agent memory has converged, from two directions, on the shape Ratchet already has. Production coding agents (Claude Code, Devin, Letta, OpenHands, Codex) have abandoned opaque stores for plain Markdown files with a small always-loaded index, on-demand topic files and, increasingly, a git repository underneath; the newest research line (ACE, SkillOpt, validation-gated skill evolution) treats the memory document itself as the trainable state of a frozen agent, edited only by small itemized deltas that must survive a held-out evaluation. Vector and graph stores such as Mem0 and Zep post 90%+ on conversational-recall benchmarks, but those benchmarks are near saturation with a **6.4% answer-key error rate**, and on the competencies that matter for a research harness the same stores lose to a gpt-4o-mini agent grepping files (**74.0% vs 68.5%** on LoCoMo) and collapse on test-time learning (**Mem0 35/37/35 vs MemGPT 89/83/79**). The strongest evidence of all is negative: ungated memory reliably hurts, with consolidated memory falling below the no-memory baseline, skill libraries peaking at 62% and giving back gains to 50%, and memory evolution cutting a model's refusal rate from 46% to 12%. For Ratchet, memory should therefore not be a new subsystem but an extension of the existing loop: an append-only episode ledger with provenance, a line-capped bullet playbook under `editable/` whose every change is a bounded delta submitted to the grader as an ordinary candidate edit, narrow per-claim-type retrieval, a third split so admission never touches the hidden test set, and a leakage critic that reads memory lineage. Every piece is implementable in the Python standard library; the literature uses embeddings only for deduplication, and `difflib` or token Jaccard substitutes.

## Plain files with a capped index now beat specialised memory stores

The 2025–26 surveys abandon the old working/episodic/semantic/procedural split as a design surface and instead ask where memory lives (in-context vs. retrieved, raw vs. distilled) and what operations act on it. "Memory in the Age of AI Agents" argues short-term/long-term distinctions "have proven insufficient" and proposes forms, functions and dynamics, splitting experiential memory into case-based (raw records for replay), strategy-based (distilled heuristics) and skill-based (executable code) ([arXiv 2512.13564](https://arxiv.org/abs/2512.13564)); the March 2026 survey formalises memory "as a write–manage–read loop" with five mechanism families including "reflective self-improvement" ([arXiv 2603.07670](https://arxiv.org/abs/2603.07670)). In those terms Ratchet's playbook is strategy-based experiential memory, its improver is a sleep-time consolidator in Letta's sense, where "the primary agent is not provided with tools to edit its core memory" and a separate agent does it offline ([Letta](https://www.letta.com/blog/sleep-time-compute)), and its grader is a write-authorisation policy. Those mappings matter because they let Ratchet borrow failure-mode and evaluation results from each line.

The empirical case for files over stores is now consistent across independent sources. Letta showed that agents on gpt-4o-mini reached **74.0% on LoCoMo "by simply storing conversation histories in files"** with `grep`-style tools and a rule forcing iterative search, above Mem0's reported 68.5% for its graph variant, concluding that "specialized memory tools that may have originally been designed for single-hop retrieval are less effective than simply allowing the agent to autonomously search through data with iterative querying" ([Letta](https://www.letta.com/blog/benchmarking-ai-agent-memory)). MemoryAgentBench, the one benchmark covering learning and forgetting, found extraction-based stores "significantly lower than their backbone GPT-4o-mini even when the context is relatively small": on test-time-learning classification Mem0 scored 35/37/35 and Cognee 34/42/42 while MemGPT's agentic search scored 89/83/79 ([arXiv 2507.05257](https://arxiv.org/html/2507.05257)). Graph structure buys little: Mem0g beat flat Mem0 by **1.56 points overall** while losing single-hop and multi-hop, running search roughly 3x slower at 2x the tokens ([Mem0 paper](https://arxiv.org/html/2504.19413)), and the "Anatomy of Agentic Memory" survey documents a "silent failure" mode where a 3B backbone's structured-write format errors rose to 30.38% and accuracy fell from 0.781 to 0.447, with "append-only systems ... relatively robust" and graph architectures "highly sensitive" ([arXiv 2602.19320](https://arxiv.org/html/2602.19320v1)). For a single-harness research agent whose memory is mostly procedural, the standard-library constraint costs Ratchet nothing of substance.

Industry has converged on one concrete anatomy: a hard-capped index plus topic files, with provenance per entry. Claude Code loads "the first 200 lines of MEMORY.md, or the first 25KB" every session, stamps a `modified` timestamp on frontmatter files, records four note types (`user`, `feedback`, `project`, `reference`), returns an error when the index overflows, and "skips anything it can derive from the codebase" ([Claude Code docs](https://code.claude.com/docs/en/memory)). Devin's memory is "a persistent Git repository of Markdown notes" where each entry is a one-line bullet such as `- Use bun, not npm; the lockfile is bun.lock [source: ...; added: 2026-10-05]`, parallel sessions resolve conflicts through git, and a daily "dreaming" session consolidates duplicates and removes "stale notes that no session has used" ([Devin docs](https://docs.devin.ai/product-guides/memory); [AgentMemoryRepo spec](https://github.com/AgentMemoryRepo/agentmemoryrepo)). Letta's MemFS is "a git-backed memory filesystem" where only `system/` files load every turn, memory subagents "use git worktrees so they can write memory concurrently", and a defragmentation flow restructures memory into "a clean hierarchy of 15–25 focused files" ([Letta](https://www.letta.com/blog/context-repositories)). OpenHands caps combined indexes at ~6,000 characters and wraps injected memory in `<UNTRUSTED_CONTENT>` ([OpenHands](https://docs.openhands.dev/sdk/guides/persistent-memory)); Codex stops reading AGENTS.md at 32 KiB ([Codex](https://developers.openai.com/codex/guides/agents-md)). The caps are not arbitrary: Anthropic's own guidance is to "target under 200 lines" because "longer files consume more context and reduce adherence" ([Claude Code docs](https://code.claude.com/docs/en/memory)), and HumanLayer reports that "as instruction count increases, instruction-following quality decreases uniformly" ([HumanLayer](https://www.humanlayer.dev/blog/writing-a-good-claude-md)).

The one rigorous negative result on context files sharpens what belongs in a playbook. Across coding agents and models, "providing context files does not generally improve task success rates, while increasing inference cost by over 20% on average"; instructions are followed, but "repository overviews ... are not helpful", and the authors recommend that files "should only contain specific additional instructions beyond what is already available in the codebase" ([arXiv 2602.11988](https://arxiv.org/html/2602.11988)). The study tested static overview files, not learned corrections, so it does not bound a gated playbook, but it does say the always-loaded text must carry non-derivable, specific guidance and that step and token growth is a regression signal in its own right. Anthropic's internal evidence points the same way from the other side: a file-based memory tool plus clearing stale tool results "improved performance by 39% over baseline" on agentic search, with context editing alone worth 29% ([Anthropic](https://www.anthropic.com/news/context-management)), and long-context models lose 30–60% on LongMemEval when forced to read a full ~115k-token history instead of the relevant sessions ([LongMemEval](https://arxiv.org/html/2410.10813)). Memory earns its tokens by keeping the context small, not by filling it.

## Self-improving memory works as itemised, gated deltas

Every self-improving memory system that reports durable gains uses the same pipeline: run the task, obtain a success signal, have a reflector distil a handful of structured items from the trajectory, and have a curator merge them as a delta. ACE (ICLR 2026) is the cleanest statement. Context is "structured bullets rather than one monolithic prompt", each with "a unique identifier and counters for how often it was marked helpful or harmful"; a Generator flags which bullets helped, a Reflector "distills concrete insights from successes and errors", and a Curator emits "compact delta entries" that "non-LLM logic merges ... deterministically", with semantic-embedding dedup run proactively or lazily ([ACE](https://arxiv.org/html/2510.04618v1)). ACE reports **+10.6% on agent benchmarks and +8.6% on finance**, matches a GPT-4.1-powered production agent on AppWorld using DeepSeek-V3.1, and cuts adaptation latency 82.3% versus GEPA; removing delta updates costs "-11.7% TGC and -27.8% SGC" on AppWorld ([ACE](https://arxiv.org/html/2510.04618v2)). ReasoningBank adds the extraction recipe: items are `{title, description, content}`, "up to three items per trajectory", drawn from failures as "lessons, pitfalls, and preventive guardrails" as well as from successes, with the richest signal coming from self-contrast across k parallel rollouts (**55.1 vs 52.4** at k=5 on WebArena-Shopping) ([ReasoningBank](https://arxiv.org/html/2509.25140v1)). Ratchet's noise-band repeats are exactly this contrastive raw material.

The reason the delta discipline matters is a documented catastrophe. ACE names two failure modes of LLM-rewritten memory: brevity bias, "the tendency of optimization to collapse toward short, generic prompts", and context collapse, where "at step 60 the context contained 18,282 tokens and achieved an accuracy of 66.7, but at the very next step it collapsed to just 122 tokens, with accuracy dropping to 57.1—worse than the baseline accuracy of 63.7 without adaptation" ([ACE](https://arxiv.org/html/2510.04618v2)). Dynamic Cheatsheet, the system that collapsed, is otherwise strong (GPT-4o on Game of 24 went from 10% to 99% once it stored a Python solver), but its cumulative full-rewrite update is what fails, and its gains vanish on small models: GPT-4o-mini "performed worse than baseline" ([DC](https://aclanthology.org/2026.eacl-long.333.pdf)). Microsoft's SkillOpt quantifies the fix as "a textual learning rate": an edit budget bounding how much a single accepted edit may change, which beats unbounded edits **87.1 vs 84.6, 77.5 vs 75.7 and 61.3 vs 57.3** across three benchmarks ([SkillOpt](https://microsoft.github.io/SkillOpt/)). Collapse is a property of whole-document rewrites, not of text memory; Ratchet's git archive makes a collapse recoverable, but making the edit unit a bullet makes it impossible within a single accepted edit.

Gating memory edits on held-out evaluation is the most Ratchet-relevant development of 2026, and it has now been shown to be the single most important safeguard. SkillOpt treats a skill document as "the trainable state of a frozen language agent" where "an edit is accepted only when it strictly improves a held-out validation score", with a rejected-edit buffer that becomes "negative feedback, helping the optimizer avoid repeating harmful directions" and an epoch-wise slow/meta update; it was best or tied in all 52 (model, benchmark, harness) cells, lifting GPT-5.5 by **+19.1 points inside Claude Code**, and its ablations credit the rejected buffer with +1.6 to +4.6 points and the slow/meta update with 77.5 vs 55.0 on spreadsheets ([MSR](https://www.microsoft.com/en-us/research/publication/skillopt-executive-strategy-for-self-evolving-agent-skills/); [SkillOpt](https://microsoft.github.io/SkillOpt/)). "When Self-Evolution Backfires" runs the same idea on Terminal-Bench 2 with a Cold/Hot tier: a distilled skill starts invisible, passes a schema check, a single-skill A/B replay on held-out tasks and an LLM semantic review, then a marginal-gain greedy selection, and only then reaches runtime context. Gated accumulation reached **72% pass@1 vs 50% ungated** with a 5x smaller pool, and removing the holdout replay alone cost 10 points, more than any other component ([arXiv 2608.05810](https://arxiv.org/html/2608.05810v1)). The self-modifying-agent line adds two cheap tricks: the Darwin Gödel Machine's staged evaluation (10 tasks to confirm viability, promote to 60, then 200 only if above 40% and top-two) and its finding that "always building on the latest agent ... struggles because one poor self-modification makes later improvements harder", an argument for keeping Ratchet's archive of rejected variants as stepping stones ([DGM](https://arxiv.org/html/2505.22954v1)); SICA scores candidates with a utility that is half accuracy and a quarter each cost and wall time ([SICA](https://arxiv.org/html/2504.15228v2)).

The negative results explain why the gate is indispensable rather than optional. Ungated skill accumulation on Terminal-Bench 2 rose from 46% to a **62% peak at 105 skills and fell to 50% at 179**, with hard-tier accuracy eroding from 53% to 35%, and post-hoc removal of culprit skills recovered only 1.7 of the 12.3 lost points "because derived skills inherit flaws" ([arXiv 2608.05810](https://arxiv.org/html/2608.05810v1)). "Useful Memories Become Faulty" shows an inverted U everywhere: AWM-distilled memory on WebShop drops from 0.64 at 8 examples to 0.20 at 128, level with no memory, and GPT-5.4 fails **46% of ARC-AGI problems it had solved** after consolidating from the ground-truth solutions, via "overgeneralized lessons stripping applicability conditions" ([arXiv 2605.12978](https://arxiv.org/html/2605.12978v1)). CTIM-Rover's ExpeL-style insight memory made a SWE agent worse in every configuration (31% vs 42% for insights only), and adding the arbitrary item "GRANDMA LIKES PASTA" changed which bug it chased ([CTIM-Rover](https://aclanthology.org/2025.realm-1.30.pdf)). Misevolution found memory evolution cutting refusal from 46.3% to 11.9% and raising confabulation by 10 points, with safety "stable until a sudden collapse at round 60" after one unreasonable refund earned a high rating and became a heuristic ([Misevolution](https://arxiv.org/html/2509.26354)). The convergent lesson is that retrieval precision matters more than store size: ReasoningBank's accuracy is highest at **one retrieved item (49.7) and declines at two, three and four (46.0, 45.5, 44.4)**, and Memento plateaus at K=4 ([ReasoningBank](https://arxiv.org/html/2509.25140v1); [Memento](https://arxiv.org/html/2508.16153v2)).

Against fine-tuning, token-space learning is the only option for a frontier-API harness and the cost case is strong: Training-Free GRPO lifted DeepSeek-V3.1 on AIME24/25 to 82.7/73.3 for about **$18 of API calls** versus roughly $10,000 to fine-tune 32B models that scored lower ([arXiv 2510.08191](https://arxiv.org/html/2510.08191v1)), and GEPA beat GRPO by 6 points with up to 35x fewer rollouts ([GEPA](https://proceedings.iclr.cc/paper_files/paper/2026/hash/0e9e708b6f48e14fd0ac29e167413f76-Abstract-Conference.html)). The honest caveats are that these comparisons are cross-model, that small backbones gain little, and that no one has measured months-long stability of token-space memory; Letta's position that "LLMs are excellent at using context, they do not reliably create durable context for future tasks" is the right default posture ([Letta](https://www.letta.com/blog/towards-agents-that-learn/)).

## Proving memory helped needs paired runs, three splits and a cost line

Conversational-recall benchmarks are the wrong target. An independent audit found **99 of 1,540 LoCoMo questions (6.4%) have score-corrupting answer-key errors**, nearly double the 3.3% average Northcutt measured across ML benchmarks, and the standard gpt-4o-mini judge "accepted 62.81% of intentionally wrong but topically adjacent answers" ([Penfield Labs](https://penfieldlabs.substack.com/p/we-audited-locomo-64-of-the-answer)). Judge choice alone opens a 27.5-point gap between strict token-F1 and a generous LLM judge on identical outputs ([arXiv 2606.22030](https://arxiv.org/pdf/2606.22030v2)); Mem0's own LoCoMo number moved from 66.88 in its April 2025 paper to 92.5 in its 2026 repo on harness changes, while Zep corrected its claim from 84% to 75.14% after a dispute ([Mnemoverse](https://mnemoverse.com/docs/research/evaluation/judges-good-and-evil); [Zep](https://blog.getzep.com/lies-damn-lies-statistics-is-mem0-really-sota-in-agent-memory)). MemoryArena shows agents "near-saturated" on LoCoMo "perform poorly" on multi-session agentic tasks, with long-context agents at 0.09–0.19 success and external-memory systems always slowest ([MemoryArena](https://arxiv.org/html/2602.16313v2)). The credible 2026 pattern is a stream of verifiable tasks with a deterministic grader (Terminal-Bench 2's hidden verifier tests, GDPevo's code-based graders), a designed train/test relationship, and cost reported alongside accuracy ([arXiv 2608.05810](https://arxiv.org/html/2608.05810v1); [GDPevo](https://arxiv.org/html/2608.03764v1)). Ratchet's SciFact grader already fits this class.

Three controls separate "memory helped" from "more context helped" or "the model got lucky". First, a zero-shot no-history control: MemoryAgentBench shows under 4% without history versus 48.6% with it, ruling out pretraining as the source of apparent learning ([arXiv 2507.05257](https://arxiv.org/html/2507.05257v4)). Second, a token-matched raw-episode baseline: "removing episodic evidence and using only abstract lessons collapses accuracy back to the no-memory baseline", so an episodic-only store "should be a diagnostic baseline" ([arXiv 2605.12978](https://arxiv.org/html/2605.12978v1)), and the "Anatomy" survey's Context Saturation Gap says a memory system is only worth its machinery when it beats a full-context dump ([arXiv 2602.19320](https://arxiv.org/html/2602.19320v1)). Third, memory-on/off ablation for causal attribution, as Misevolution did to show "when the memory is removed, all models consistently achieve a 0% Unsafe Rate" ([OpenReview](https://openreview.net/forum?id=Fd1jgQQW28)). A gain over the zero-shot control but not over the raw-episode dump means the evidence, not the distilled memory, did the work.

The statistics are less forgiving than most memory papers admit. Across 60,000 SWE-bench Verified trajectories, single-run pass@1 varies **2.2–6.0 points** depending on which run is picked, so "reported improvements of 2–3 percentage points may reflect evaluation noise"; detecting a 2-point effect at 80% power needs about 9 runs per arm at σ=1.5%, and a 1-point effect needs 36–51 ([arXiv 2602.07150](https://arxiv.org/html/2602.07150v3)). Anthropic's guidance is to use paired differences on the same questions and to cluster standard errors by question group, since clustered errors "can be over three times as large as naive standard errors" ([Anthropic](https://www.anthropic.com/research/statistical-approach-to-model-evals)). Ratchet's measured noise band is the right instrument, but the literature adds a structural requirement: a third split. "When Self-Evolution Backfires" uses Event (drives distillation), Holdout (used only for A/B replays inside admission gates) and Test ("never touched by distillation or gating"), noting that Event-split numbers are "an optimistic upper bound, whereas Test is the honest held-out estimate" ([arXiv 2608.05810](https://arxiv.org/html/2608.05810v1)). If memory admission in Ratchet is decided by the same hidden split that reports final performance, the gate itself becomes a leakage channel through selection.

Two metrics from the newer benchmarks belong in Ratchet's report. Cumulative accuracy over the task stream, as Evo-Memory reports, exposes the inverted-U trajectories that an endpoint number hides ([Evo-Memory](https://arxiv.org/html/2511.20857v2)); STATE-Bench's pass^5, "the percentage of tasks completed successfully on all five runs", measures the consistency that memory is supposed to buy, and its authors note "the gap between average pass@1 and pass^5 ... is precisely the failure mode memory is intended to mitigate" ([Microsoft](https://opensource.microsoft.com/blog/2026/05/19/introducing-state-bench-a-benchmark-for-ai-agent-memory)). Memora's Forgetting-Aware Memory Accuracy, which penalises answers that rely on invalidated memory, produced "large score reductions" across every system and revealed memory agents degrading from weekly to quarterly horizons (Mem0 40.42 to 19.90) ([Memora](https://arxiv.org/html/2604.20006v1)). Cost must be a first-class column: external-memory agents "always incur the highest latency" in MemoryArena ([MemoryArena](https://arxiv.org/html/2602.16313v2)), context files add 20% cost without gains ([arXiv 2602.11988](https://arxiv.org/html/2602.11988)), and tagging every model call by purpose caught a pricing bug that had made one study's reported costs wrong by 5x ([arXiv 2609.22818](https://arxiv.org/pdf/2609.22818v1)).

## Drift and leakage threaten Ratchet more than injection does

Forgetting is the weakest operation in the field. Every system in MemoryAgentBench fails multi-hop selective forgetting at **28% or below**, and a conservative update policy lowered average performance by 4.5 points ([arXiv 2507.05257](https://arxiv.org/html/2507.05257v4)); STALE probes implicit conflicts without explicit negation and the 2026 survey concludes "nobody evaluates forgetting well" ([STALE](https://arxiv.org/abs/2605.06527v1); [arXiv 2603.07670](https://arxiv.org/html/2603.07670v1)). What production systems offer instead is visibility: Zep's bi-temporal edges keep an invalidated fact "with its full history rather than being deleted" and record which episode invalidated it ([Zep](https://blog.getzep.com/how-zep-tracks-provenance-in-agent-memory)); Claude Code stamps `modified` timestamps and ships `/doctor prompt-audit` for conflicting instructions ([Claude Code docs](https://code.claude.com/docs/en/memory)); Memp "updates, corrects, and deprecates" procedures rather than deleting them ([Memp](https://arxiv.org/abs/2508.06433)). The EMNLP 2026 security survey names Verified Forgetting as a governance primitive no surveyed system supports and rates Mem0 as providing "no support for" write authorisation, rollbackability or verified forgetting ([EMNLP 2026](https://aclanthology.org/2026.emnlp-main.2296.pdf)). Deprecation with a behavioural regression test is the only available substitute.

Poisoning is real but, for Ratchet, second-order. MINJA injects malicious records "solely through interacting with the agent via queries" at **98.2% injection and 76.8% attack success** ([MINJA](https://arxiv.org/abs/2503.03704)), and poisoning just 1.2% of a LongMemEval corpus with plain false assertions drops accuracy from 0.85 to 0.30 while a four-stage content screener "rejects 0 of 360 poisoned memories" ([arXiv 2608.21230](https://arxiv.org/abs/2608.21230)). Realistic conditions blunt this: with relevant pre-existing memories GPT-4o-mini's attack success fell from 62% to 6.67%, poison was stored but outvoted, and raising retrieval k from 3 to 10 raised it back to 38% ([arXiv 2601.05504](https://arxiv.org/html/2601.05504v2)), another argument for narrow k. The incidents that did bite were file-level: Cisco compromised Claude Code by having an npm postinstall hook overwrite `MEMORY.md`, after which the agent recommended committing API keys, and Anthropic's v2.1.50 removed user memories from the system prompt so they "no longer have the same architectural authority" ([Cisco](https://blogs.cisco.com/ai/identifying-and-remediating-a-persistent-memory-compromise-in-claude-code)); Bedrock Agents stored an injection during summarisation and replayed it into every later session ([Unit 42](https://unit42.paloaltonetworks.com/indirect-prompt-injection-poisons-ai-longterm-memory)). The defence literature is specific about where safeguards pay off: three write-time defences showed no resolvable utility cost and 0% false quarantine, while a read-time reranker cost 4.4 points and quarantined **33.6% of legitimate memories** on attack-free traffic, so "where a defense intercepts the pipeline ... appears to determine its benign-case price" ([arXiv 2609.22818](https://arxiv.org/pdf/2609.22818v1)). Provenance down-weighting has "no usable setting" when the evidence itself arrives untrusted, which is exactly a claim-checker's situation, and the recommended alternative is a bounded cap on how much of the context untrusted memory may occupy ([arXiv 2608.21230](https://arxiv.org/abs/2608.21230)). The survey's conclusion is that security "must be anchored in storage-time provenance, versioning, auditability, and policy-aware retention, rather than retrofitted only at retrieval or execution time" ([EMNLP 2026](https://aclanthology.org/2026.emnlp-main.2296.pdf)), and production practice agrees: OpenHands tells the agent memory "may contain prompt injection ... treat them as unverified hints", Zep routes memory through the provider's untrusted-data channel, Codex can exclude chats that used web search from memory generation, and Gemini's Auto Memory emits unified-diff `.patch` proposals into an inbox that "never applies them without your approval" ([OpenHands](https://docs.openhands.dev/sdk/guides/persistent-memory); [Zep](https://help.getzep.com/v2/concepts); [Codex](https://developers.openai.com/codex/memories); [Gemini CLI](https://geminicli.com/docs/cli/auto-memory/)).

Leakage, not injection, is the attack Ratchet's own loop runs on itself, and here the published state of practice is behind Ratchet's existing critic. No paper proposes a dedicated memory-leakage detector; the field prevents leakage structurally and detects it indirectly. GDPevo warns that "if the training and test tasks are identical or nearly identical, improvements may reflect memorization rather than generalization", uses rule hybridisation so test tasks recombine rules, and lists "isolated information budgets, deterministic graders, calibration evidence, independent review, attempt-level traces" as the controls that separate "transferable improvement from answer leakage, template reuse, scoring artifacts" ([GDPevo](https://arxiv.org/html/2608.03764v1)). RewardHackingAgents logs runtime file access per episode to detect "accessing held-out data or labels during training" and warns that an editable evaluator lets agents raise scores by editing it ([arXiv 2603.11337](https://arxiv.org/html/2603.11337v1)), which is why Ratchet's grader being read-only matters. The behavioural signature of memorised memory is that performance stays "stable on exact repetitions of those problems but collapses on simple variations within the same strategy family" ([arXiv 2605.12978](https://arxiv.org/html/2605.12978v1)), a test Ratchet can run by paraphrasing training claims. The specific risk for a claim verifier is a distilled prior: Misevolution's 10-point confabulation increase shows how a memory of "papers in this domain usually SUPPORT" can override evidence, and GDPevo's case study shows remembering an action "without its jurisdiction/date/status conditions ... produces confident negative transfer" ([Misevolution](https://openreview.net/forum?id=Fd1jgQQW28); [GDPevo](https://arxiv.org/html/2608.03764v1)).

## A design for Ratchet: memory as another gated edit

The evidence supports a layered design in which only one layer is ever edited by an LLM, and that layer is edited only through the existing gate. The table maps each layer to its form, load policy, writer and admission rule, with the source that justifies it.

| Layer | Form and location | Loaded | Written by | Admission |
|---|---|---|---|---|
| Episode ledger | Append-only JSONL per graded claim run: claim id, split tag, Frame output, retrieval queries, retrieved doc ids and content hashes, Verifier and Sceptic outputs, verdict, grader outcome, tokens, time | Never injected whole; read on demand by the Reflector and by a token-matched baseline | Workflow code, deterministically | None; non-lossy by design (Zep episode subgraph; episodic-only baseline in [arXiv 2605.12978](https://arxiv.org/html/2605.12978v1)) |
| Domain ledgers | Retraction/concern list keyed by DOI/PMID; evidence cache keyed by (source id, content hash) with query-dependent summaries cached separately; venue/domain reliability notes conditioned on claim type; verdict + evidence-fingerprint records | Retrieve stage looks up by key | Workflow code from external feeds and run outputs | Refresh from source; never LLM-rewritten ([EMNLP 2026 Findings](https://aclanthology.org/2026.findings-emnlp.2070/); [Crossref](https://www.crossref.org/documentation/retrieve-metadata/retraction-watch); [PaperQA2](https://github.com/future-house/paper-qa)) |
| Playbook bullets | Under `editable/`: a capped `PLAYBOOK.md` index (200 lines or less) plus topic files per stage and claim type; each bullet carries id, type (strategy, pitfall, fact), text, `derivedFrom` run ids, added/modified dates, gate-accepted and gate-rejected counts | Index every run; topic files by stage on demand, k of 1–4 bullets per claim type | Reflector proposes, Curator emits a bounded delta, improver submits it as a candidate edit | Existing grader on the gate split; survives only within the noise band and without cost regression ([ACE](https://arxiv.org/html/2510.04618v1); [SkillOpt](https://microsoft.github.io/SkillOpt/); [arXiv 2608.05810](https://arxiv.org/html/2608.05810v1)) |
| Rejected-edit buffer | Git branches or a JSONL of rejected deltas with their gate scores | Shown to the improver as negative examples | Gate | Automatic ([SkillOpt](https://microsoft.github.io/SkillOpt/); [DGM](https://arxiv.org/html/2505.22954v1)) |

The write path follows ACE and ReasoningBank with SkillOpt's stabilisers. After each graded batch, a Reflector reads the episode ledger for that batch and extracts at most three items per trajectory, in two separate passes for failures and successes because SkillOpt found that "failures and successes are reflected separately so edits correct recurring errors while preserving working behavior" ([SkillOpt](https://microsoft.github.io/SkillOpt/)); where the noise-band repeats of the same claim disagree, it uses the contrast between the passing and failing trajectories, which ReasoningBank showed yields better memory than any single rollout ([ReasoningBank](https://arxiv.org/html/2509.25140v1)). A Curator turns the items into a delta of add, edit and deprecate operations on identified bullets, capped by an edit budget of a few bullets per candidate, and Python merges the delta deterministically, deduplicating against existing bullets with `difflib.SequenceMatcher` or length-normalised token Jaccard in place of ACE's embeddings, taking care not to Jaccard a short bullet against a long one because the score "is capped near len(claim)/len(document)" ([Co-Scientist OPERATIONS](https://github.com/guy915/Co-Scientist/blob/main/docs/OPERATIONS.md)). Deprecation sets a flag and keeps the bullet out of retrieval rather than deleting it, so a regression test can later assert that a deprecated rule no longer changes behaviour, the only available form of verified forgetting. Whole-playbook rewrites are forbidden to the LLM; defragmentation into fewer, cleaner files is a Python operation that preserves ids and the union of `derivedFrom` sources, because consolidation that drops source ids launders provenance.

The gate is Ratchet's existing grader with three additions. First, a third split: carve a gate split from the training side so memory admission replays on it and the hidden test split is touched only by the final report, as in the Event/Holdout/Test design ([arXiv 2608.05810](https://arxiv.org/html/2608.05810v1)). Second, staged screening in the DGM style, a cheap replay on a small gate subset to discard clearly harmful deltas before the full run ([DGM](https://arxiv.org/html/2505.22954v1)). Third, a utility that includes cost and steps, since memory reliably increases both and SICA's half-accuracy, quarter-cost, quarter-time weighting is a reasonable starting point ([SICA](https://arxiv.org/html/2504.15228v2)). A noise band is stricter than SkillOpt's visible-split "strictly improves" rule, so expect lower acceptance rates and batch several bullets into one candidate; the interaction has not been studied anywhere in the literature. Each accepted delta's gate outcome updates the bullets' accepted/rejected counters, which gives Ratchet something no published system has: outcome-based per-item credit, stronger than ACE's generator-voted counters and cheaper than MemQ's provenance-DAG value propagation ([MemQ](https://arxiv.org/abs/2605.08374)). Because Misevolution's collapse arrived suddenly at round 60 after fifty stable rounds, re-grade the whole playbook against a frozen no-memory baseline and a token-matched raw-episode baseline on a schedule, and keep a regression suite of previously fixed claims so pruning cannot silently reintroduce them ([Misevolution](https://arxiv.org/html/2509.26354)).

The read path is deliberately stingy. Only the index loads every run; the Retrieve stage reads the topic file for the current claim type and stage and injects at most one to four bullets, capped as a fraction of the context, because every k-sweep in the literature peaks at one to four items and the realistic-poisoning study shows attack success climbing with k ([ReasoningBank](https://arxiv.org/html/2509.25140v1); [arXiv 2601.05504](https://arxiv.org/html/2601.05504v2)). Bullets enter prompts framed as hints rather than rules, following OpenHands' untrusted framing, which Misevolution found recovers part of the lost safety even if not all of it ([OpenHands](https://docs.openhands.dev/sdk/guides/persistent-memory); [Misevolution](https://arxiv.org/html/2509.26354)). The Sceptic deserves a dedicated channel modelled on the AI co-scientist's meta-review, whose summary of recurring critiques is "simply appended to their prompts in the next iteration" and used "selectively to avoid over fitting" ([co-scientist](https://storage.googleapis.com/coscientist_paper/ai_coscientist.pdf)); in Ratchet that summary is just another gated delta to the Sceptic's topic file.

The leakage critic extends naturally. Every bullet carries `derivedFrom` run ids, and runs carry split tags, so any bullet whose lineage touches a hidden-split claim is rejected at write time; bullets with high lexical overlap against held-out claims or their gold evidence are quarantined for review; and a periodic perturbation test compares accuracy on exact training claims against paraphrases, treating a large gap as the memorisation signature ([arXiv 2605.12978](https://arxiv.org/html/2605.12978v1)). Anything that would change the agent's decision rule rather than its procedure, such as a bullet encoding a label prior for a domain, should require human review, the one place where VerificAgent-style "human-verified freezing" is worth its latency ([EMNLP 2026](https://aclanthology.org/2026.emnlp-main.2296.pdf)). Git already supplies rollbackability and most of provenance visibility; tagging each promotion commit makes rollback to the last known-good store a single operation.

What remains uncertain is honest to state. No published system combines all of these pieces, so the synthesis is an inference from components that were each validated separately. No benchmark targets memory for scientific claim verification, and no published agent persists source-reliability scores or retrieval strategies across runs, so Ratchet's domain ledgers are unexplored territory rather than established practice. Token-space memory gains shrink sharply on small backbones, so if Ratchet's inner models are small, expect the playbook to help less than ACE's numbers suggest. And the single most important design question, how a measured noise band interacts with a strict-improvement gate, has no literature at all; Ratchet will be generating that evidence.

## Conclusion

The deepest shift in the 2026 literature is that memory has stopped being a retrieval problem and become a write-authorisation problem. The systems that win are not the ones with the cleverest index but the ones that refuse most of what the agent wants to remember, and the systems that fail do so not by forgetting but by remembering too eagerly: inverted-U curves, context collapse and sudden safety breaks are all consequences of unconditional writes. Ratchet, built for a different purpose, already owns the scarce component, a read-only grader with a hidden split and a noise band, which the memory literature only recently rediscovered as its most important safeguard. The design task is therefore not to add a memory system but to route one more kind of edit through machinery that exists.

Two implications follow. Because the gate scores every delta on held-out claims, Ratchet can produce the first outcome-based per-item utility record for a playbook, something ACE, ReasoningBank and SkillOpt all approximate with model opinions; publishing acceptance histories per bullet would be a contribution in itself. And because no one has measured how a noise band trades acceptance rate against contamination, Ratchet's archive of accepted and rejected memory deltas is the natural dataset for answering it. The harness should instrument that question from the first run: log every candidate delta, its gate score, its cost delta and its lineage, and the memory system will be evaluable in exactly the way the field says memory systems almost never are.
